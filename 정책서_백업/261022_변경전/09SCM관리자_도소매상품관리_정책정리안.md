# 09SCM관리자 — 도소매 상품관리 정책정리안

기준일: 2026-10-20
범위: 도매관리 > 내 도매상품(도매상품등록·수정) / 소매관리 > 상품관리(상품목록, 상품카테고리, 소매상품등록, 소매정보등록·수정, 도매상품전환, 메인상품진열)
관련 문서: `09SCM관리자_도매주문처리_정책정리안` (주문·결제·배송·취소반품 처리), `09SCM관리자_소매몰설정_정책정리안` (기본 수령방식), `09SCM관리자_소매주문처리_정책정리안` (소매 주문 접수·취소·반품 재고 처리), `09SCM관리자_로그인_정책정리안` (이용상태별 판매 행위 범위), `09SCM관리자_가맹점이용상태이용료정기결제_정책정리안` (이용불가 전환·도매공급권한 회수 시 상품 일괄 처리), `09SCM관리자_채팅주문_정책정리안` (채팅주문상품명)

## 1. 결론 요약

- 상품코드는 도매·소매 구분 없이 하나의 코드 체계("P" + 4자리 숫자, 예: P0231)로 시스템 전체에서 유일하게 채번한다. 도매상품/소매상품 구분은 코드가 아니라 상품출처(내도매상품·도매주문상품·내소매상품) 필터값으로 한다(2-2절).
- 도매상품과 소매정보는 별도 엔티티다. 상품코드는 도매주문상품·내도매상품·내소매상품 어느 출처든 동일한 코드를 일괄 공유하며, 상품출처에 따라 각 상태 전환 규칙이 정해진다. 소매정보는 소매몰(본사·가맹점)마다 독립적으로 설정한다. 한 소매몰 안에서 같은 상품코드의 소매정보는 1개다(2-3절). 보유수량은 계정 + 상품코드 단위로 저장하며 소매·도매 주문, 취소·반품 재고 반영, 배송확정에 따라 증감한다(3절).
- 소매정보의 상품출처는 내도매상품·도매주문상품·내소매상품(소매몰 단독 등록) 3가지다. 내소매상품은 도매상품전환 화면을 통해 도매몰로 전환할 수 있으며, 전환은 되돌릴 수 없는 처리다. 전환해도 상품코드는 유지한다(재채번 없음). [도매상품전환]은 도매공급권한을 보유한 계정(본사 포함)에게만 노출되며, 이용제한 상태에서는 버튼 작동과 전환 화면 진입이 모두 차단된다(`09SCM관리자_로그인_정책정리안` 6절).
- 도매주문상품 소매정보는 주문 단위가 아니라 상품(코드) 단위로 만든다. 같은 상품을 다시 구매(배송확정)하면 기존 소매정보의 보유수량이 누적된다(2-4절).
- 소매판매상태·소매노출여부의 잠금은 두 가지 독립된 조건으로 결정된다 — ① 연동재고(보유수량) 소진 여부(판매상태·노출여부 모두 잠금), ② 픽업가능종료일 경과 여부(수령방식이 픽업 또는 픽업+배달인 소매정보에 한함, 노출여부만 강제 미노출로 잠금). 픽업가능종료일 경과는 판매상태에 영향을 주지 않으며 판매상태는 수량 기준으로만 결정된다. 잠기지 않은 나머지 필드는 계속 자유롭게 수정할 수 있다.
- 화면 접근(조회·수정 진입) 자체를 막는 것은 ①(연동재고 소진) 조건 중에서도 다른 재고에 종속된 소매정보(내도매상품·도매주문상품)뿐이다. 자체 재고를 보유하는 상품(도매상품, 내소매상품)은 재고 소진과 무관하게 화면 접근이 항상 허용되며, 픽업가능종료일 경과는 어떤 상품출처든 화면 접근 자체를 막지 않는다.
- 도매상품등록·소매정보등록 모두 등록 시점에 입력한 수량이 0이면 품절, 0 초과면 판매중으로 자동 산정되며 별도 선택 단계는 없다.
- 상품 신규 등록 시 수령방식 초기값은 소매설정의 기본 수령방식을 따른다. 상품별로 변경할 수 있고 이미 등록된 상품에는 영향이 없다(8절).
- 도매상품의 공급범위가 우리지역이면 상품별로 등록 지역(시·군·구 단위)을 등록한다. 기본 지역은 공급자 사업장 주소의 시·군·구이며 삭제할 수 없고, 추가 지역을 포함해 최대 50곳까지 등록한다. 신규 등록 시 도매설정의 등록 지역을 초기값으로 복사하며, 이후 도매설정을 바꿔도 이미 등록된 상품에는 영향이 없다(8-2절).
- 메인상품진열은 소매몰에 노출 중인 소매상품만 대상으로 하며, 노출여부가 미노출이 되면 진열에서 자동 삭제된다(12절).
- 가맹점을 이용불가로 전환하면 시스템이 해당 가맹점이 등록한 도매상품과 소매정보 전체를 즉시 품절·미노출로 일괄 처리한다. 도매공급권한을 회수하면 도매상품만 같은 방식으로 처리하고 소매정보는 유지한다. 두 경우 모두 수량은 바꾸지 않으며, 이용불가 해제·이용승인·공급권한 재부여 후에도 자동 복구하지 않는다(4-4절).- 판매자 본인의 보유수량은 도매 주문이 발생하는 즉시(접수처리 시점이 아님) 차감되며, 취소·반품이 승인으로 확정될 때 재고를 복원할지는 판매자가 체크박스로 선택한다(3절).
- 소매몰에서 주문이 접수되는 즉시 해당 소매정보의 판매가능수량과 보유수량이 주문 수량만큼 함께 감소한다(3-2절). 판매가능수량은 보유수량 중 소매 판매용으로 배정한 수량이다. 예: 보유수량 100개 중 소매 판매가능수량을 50개로 지정하면 소매몰에서는 50개까지 판매된다.
- 소매정보의 상품출처는 공급자명을 붙이지 않고 출처 구분만 노출한다(2-1절).
- 소비기한은 날짜 형식이 아닌 자유 텍스트로 입력한다(예: 수령 즉시, 당일 섭취, 수령 후 7일). 입력한 문구를 상세·수정 화면에 그대로 표시하며 날짜 비교·자동 처리에는 사용하지 않는다.
- 상품 목록·상세에는 등록일시·수정일시(도매등록일시·소매등록일시 등)를 표시한다. 일시·날짜·기간 표기 형식은 디자인시스템 문서의 "날짜·일시 표기"를 따른다. 픽업가능기간은 날짜 단위 항목이다.
- 상품목록·상품카테고리·소매상품등록·소매정보등록·소매정보 상세/수정·도매상품전환·메인상품진열 화면은 소매관리 > 상품관리 메뉴에 위치한다.
- 도매 카테고리는 시스템 고정 영역으로 모든 계정이 공통으로 사용하고, 소매 카테고리는 계정 사용자가 직접 관리한다. 두 영역은 분리되어 있다(11절).
- 삭제는 어떤 경우에도 차단하지 않는다. 진행중 주문이 있어도 삭제할 수 있으며, 확인 창에서 주문 처리 중 혼선 가능성과 복구 불가를 고지한다. 기존 주문은 주문 당시 정보(스냅샷)로 유지되어 계속 진행할 수 있고, 소비자가 보는 소매몰 상품 페이지만 사라진다(9절).

## 2. 등록 구조 개요

| 구분 | 엔티티 | 관리 화면 |
| --- | --- | --- |
| 도매상품 | 내 도매상품(파트너가 공급하는 원 상품 단위) | 도매관리 > 내 도매상품 — 도매상품등록/수정 |
| 소매정보 | 도매상품 또는 구매한 도매상품(상품 단위), 혹은 소매몰에서 직접 등록한 단독 상품을 자신의 소매몰에 노출하기 위한 판매정보 | 소매관리 > 상품관리 — 상품목록, 소매상품등록(내소매상품 신규 단독 등록), 소매정보등록·수정, 도매상품전환. 등록하지 않으면 소매몰에 노출되지 않는다 |

**소매정보의 출처(상품출처) 3가지**
1. 내도매상품: 본인이 직접 등록한 도매상품을 소매로도 판매하는 경우
2. 도매주문상품: 다른 공급자에게서 구매(배송확정)한 도매상품을 소매로 판매하는 경우(상품 단위로 소매정보를 만든다, 2-4절)
3. 내소매상품: 도매 연동 없이 소매몰에서 직접 단독으로 상품을 등록하는 경우(소매상품등록 화면에서 신규 등록). 도매상품전환 화면을 통해 도매몰로 역연결(도매상품으로 전환)할 수 있으며, 전환은 되돌릴 수 없는 처리다. 전환해도 상품코드는 유지한다.

4~7절의 노출여부·판매상태·화면 접근 규칙은 출처 성격에 따라 둘로 나뉜다 — 다른 재고에 종속된 소매정보(내도매상품·도매주문상품)와, 자체 재고를 직접 보유·관리하는 상품(도매상품·내소매상품)이다. 다만 픽업가능종료일 경과 잠금(4-1, 5절)은 상품출처와 무관하게 픽업을 포함하는 수령방식의 소매정보 전체에 동일하게 적용되는 별도 조건이다.

**소매정보 등록 경로 3가지**
1. 도매상품등록 화면에서 "소매정보 함께 등록"을 체크해 도매상품 등록과 동시에 등록(내도매상품)
2. 상품목록에서 개별 건에 대해 사후에 소매정보등록으로 진입(내도매상품·도매주문상품)
3. 소매상품등록 화면에서 도매 연동 없이 신규 단독 등록(내소매상품)

세 경로 모두 동일한 소매정보 데이터를 생성하며, 상품목록 한 곳에서 함께 조회·관리한다.

### 2-1. 상품출처 표시 규칙

소매정보 화면(소매정보등록·수정·상세, 상품목록)에 노출하는 상품출처는 공급자명을 붙이지 않고 "내도매상품" / "도매주문상품" / "내소매상품" 출처 구분값만 표시한다. 동일 공급자라도 상품마다 노출 문구가 달라지지 않으며, 목록·등록·수정·상세 전 화면에 동일하게 적용한다.

### 2-2. 상품코드 체계

| 항목 | 내용 |
| --- | --- |
| 형식 | 중립 접두 "P" + 4자리 숫자(예: P0231). 도매·소매 구분 없이 하나의 코드 체계를 쓴다 |
| 채번 | 시스템 전체에서 유일하게 채번한다. 도매주문상품·내도매상품·내소매상품 모두 동일한 상품코드를 공유한다(도매·소매 일괄 공유) |
| 도매/소매 구분 | 코드로 구분하지 않고 상품출처(내도매상품·도매주문상품·내소매상품) 필터값으로 구분한다 |
| 도매상품전환 | 내소매상품을 도매상품으로 전환해도 상품코드는 유지한다(재채번 없음) |

### 2-3. 소매정보 구조

- 상품코드는 도매·소매 전체가 공유하는 상품 식별 코드이고, 소매정보는 본사·가맹점마다 독립적으로 설정하며 소매정보 ID(내부 식별자, 사용자에게 노출하지 않음)로 구분한다. 상품코드·상품명은 화면 표시용이다.
- 한 소매몰 안에서 같은 상품코드의 소매정보는 1개다.

### 2-4. 도매주문상품 소매정보 생성 규칙

- 도매주문상품의 소매정보는 주문 단위가 아니라 상품(코드) 단위로 만든다. 한 주문에 여러 상품이 있으면 상품별로 소매정보를 만든다.
- 같은 상품을 다시 구매(배송확정)하면 기존 소매정보의 보유수량이 누적된다. 소매정보가 이미 있으면 재구매분의 상품정보로 덮어쓰지 않고 수량만 누적한다.
- 소매정보가 아직 없으면 소매정보 등록 시 가장 최근 배송확정 구매분의 상품정보를 초기값으로 사용한다.

### 2-5. 도매상품전환 규칙

- 내소매상품을 도매상품으로 전환하는 화면이며, 도매정보(도매카테고리·상품명·공급범위·공급가·공급단위·도매노출여부·보유수량·판매가능수량 등)를 새로 입력한다. 기존 소매정보(소매카테고리·소비자가·수령방식 등)는 변경 없이 그대로 유지된다.
- 전환은 되돌릴 수 없으며, 화면 상단 안내 배너("내소매상품을 도매상품으로 전환합니다. 전환 후에는 내소매상품으로 되돌릴 수 없습니다.")로 고지한다. 별도의 확인 창은 두지 않는다.
- 전환해도 상품코드는 유지하고 재채번하지 않는다. 전환이 완료되면 상품출처가 내도매상품으로 바뀌고 내 도매상품 목록으로 이동한다.
- 공급범위가 우리지역이면 등록 지역을 함께 입력하며, 초기값은 도매설정의 등록 지역이다(8-2절).
- 공급가 초기값은 기존 소비자가를 참고값으로 채우며, 실제 공급가에 맞게 수정해야 한다. 입력 검증은 13절 도매상품전환 열을 따른다.

## 3. 도매-소매 수량 연동 규칙

### 3-1. 수량 정의와 저장 단위

| 항목 | 내용 |
| --- | --- |
| 보유수량 | 계정 + 상품코드 단위로 저장하는 수량이다. 내도매상품은 공급자가 도매상품 등록·수정에서 입력한 수량, 도매주문상품은 배송확정 구매분 누적 수량, 내소매상품은 소매상품등록·수정에서 입력한 수량이다. 소매 화면과 도매 화면 모두 같은 값을 보유수량으로 표기한다 |
| 판매가능수량 | 소매정보 단위로 저장한다. 보유수량 중 소매몰 판매에 배정한 수량이다 |
| 도매 가용재고 | 저장하지 않고 산출한다. 도매 가용재고 = 보유수량 − 판매가능수량. 내도매상품에만 해당하며 도매 구매자가 주문할 수 있는 수량의 상한이다. 구매자 화면에서는 "주문가능수량"으로 표기한다 |
| 판매가능수량 상한 | 판매가능수량은 보유수량 이하여야 한다. 모든 증감 후에도 보유수량 ≥ 판매가능수량을 유지한다 |
| 보유수량 하향 수정 제한 | 보유수량은 해당 소매정보의 판매가능수량보다 낮게 수정할 수 없다 |
| 소매 등록 시 차감 | 소매정보등록으로 보유수량을 차감하지 않는다 |

### 3-2. 수량 증감 규칙 (장부 방식)

주문·취소·반품·배송확정이 발생할 때마다 아래 표대로 증감한다. 상품출처와 관계없이 보유수량은 같은 규칙으로 증감한다.

| 이벤트 | 대상 | 보유수량 | 판매가능수량 |
| --- | --- | --- | --- |
| 소매 주문 접수 | 내도매상품·도매주문상품·내소매상품 | −n | −n |
| 도매 주문 접수 | 내도매상품 (판매자 본인 상품) | −n | 변화 없음 |
| 소매 취소·반품 승인 + 재고 반영 | 소매 주문 품목 | +n | +n |
| 도매 취소·반품 승인 + 재고 반영 | 도매 주문 품목 | +n | 변화 없음 |
| 소매 구매자 즉시취소 (자동 복원, 체크박스 없음) | 소매 주문 품목 | +n | +n |
| 도매 구매자 즉시취소 (자동 복원, 체크박스 없음) | 도매 주문 품목 | +n | 변화 없음 |
| 도매 구매 배송확정 | 구매자의 도매주문상품 (계정 + 상품코드) | +n | 변화 없음 |

- n은 주문 품목 수량이다.
- 차감 시점은 주문이 생성되는 즉시이며 접수처리(주문확인·입금확인) 시점이 아니다.
- 도매 주문 접수의 차감 대상은 주문의 판매자가 본인인 건에 한한다. 타 공급자 상품을 구매하는 주문은 본인 보유수량을 차감하지 않는다.
- 소매 주문 접수는 판매가능수량 이내, 도매 주문 접수는 도매 가용재고 이내에서만 가능하다.
- 예: 보유수량 100, 판매가능수량 50(도매 가용재고 50)에서 소매 10 접수 → 보유 90 / 판매가능 40 / 가용 50. 이어서 도매 20 접수 → 보유 70 / 판매가능 40 / 가용 30. 소매 취소 재고 반영 → 보유 80 / 판매가능 50 / 가용 30. 도매 취소 재고 반영 → 보유 100 / 판매가능 50 / 가용 50.

### 3-3. 취소·반품 승인 시 재고 반영

| 규칙 | 내용 |
| --- | --- |
| 선택 방식 | 취소·반품이 승인으로 확정되는 시점에 판매자가 재고 반영 여부를 체크박스로 선택한다(기본값: 선택). 체크한 채 승인하면 해당 주문 품목 수량만큼 3-2절 표대로 복원하고, 해제하면 복원하지 않는다 |
| 체크박스 미노출 | 복원할 대상이 주문 품목 중 하나도 없으면(상품 삭제 등) 체크박스 자체를 노출하지 않는다 |
| 체크박스 노출 조건 | 요청 이력이 없는 직권 처리 건은 제출 즉시 승인이므로 항상 노출된다. 구매자 요청에 대한 조정 처리 건은 승인을 선택했을 때만 노출되며, 반려를 선택하면 노출되지 않는다. 구매자 즉시취소 건은 자동 복원이므로 체크박스를 두지 않는다 |
| 처리 단위 | 품목별 부분 취소·반품은 지원하지 않는다. 한 주문에 여러 품목이 있어도 취소·반품 처리와 재고 반영은 주문 전체 단위로 일괄 적용된다 |
| 세부 기준 | 소매 주문은 `09SCM관리자_소매주문처리_정책정리안`, 도매 주문은 `09SCM관리자_도매주문처리_정책정리안`을 따른다 |

## 4. 판매상태 정책

### 4-1. 소매 판매상태

| 조건 | 판매상태 | 노출여부 | 사용자 조작 |
| --- | --- | --- | --- |
| 보유수량 0(재고소진) — 내도매상품·도매주문상품 | 강제 품절 | 강제 미노출 | 조회만 가능, 수정 불가 |
| 보유수량 0(재고소진) — 내소매상품 | 강제 품절 | 강제 미노출 | 조회·수정 화면 진입 가능. 판매상태·노출여부 필드만 잠기며, 보유수량 필드는 계속 수정 가능(재입력 시 잠금 해제, 해제 후 값은 아래 규칙) |
| 픽업가능종료일 경과 — 상품출처 공통(내도매상품·도매주문상품·내소매상품), 수령방식이 픽업 또는 픽업+배달인 경우 | 수량 기준을 따름(판매중 또는 수량에 따른 품절) | 강제 미노출 | 조회·수정 화면 진입 가능. 노출여부 필드만 잠기며, 판매상태와 보유수량을 포함한 나머지 필드는 계속 자유롭게 수정 가능 |
| 보유수량 > 0, 판매가능수량 0 | 자동 품절 전환(잠금) | 이 조건의 영향 없음(픽업가능종료일 조건만 적용) | 판매상태만 잠금 — 판매가능수량을 다시 올리면 잠금 해제 |
| 보유수량 > 0, 판매가능수량 > 0, 픽업가능기간 이내(또는 수령방식이 배달 단독) | 자유 전환 | 자유 전환 | 전체 자유 |

위 조건은 각각 독립적으로 판정한다. 둘 이상 해당하면 각 조건이 자기 필드(판매가능수량 0은 판매상태, 픽업가능종료일 경과는 노출여부)만 잠근다.

내소매상품은 도매 연동 재고가 아니라 등록 시 직접 입력한 자체 보유수량이므로, 화면 접근(조회·수정 진입)은 도매상품과 동일하게 재고소진과 무관하게 항상 허용한다. 판매상태·노출여부만 다른 소스와 동일하게 보유수량 0 기준으로 자동 잠근다 — 재고가 없는 상태를 판매중·노출로 둘 수는 없기 때문이다.

픽업가능종료일 경과 조건은 보유수량·판매가능수량 값과 무관하게 독립적으로 작동하며, 세 가지 상품출처 모두에 동일하게 적용된다. 이 조건은 소매노출여부만 강제 미노출로 잠그고, 판매상태는 재고가 남아 있는 한 판매중으로 유지된다(수량이 소진된 경우에만 위 수량 조건에 따라 품절). 수령방식이 배달 단독인 소매정보에는 픽업가능기간 개념 자체가 없으므로 이 조건이 적용되지 않는다. 보유수량 0 조건과 달리, 픽업가능종료일 경과만으로는 화면 접근(조회·수정 진입) 자체가 제한되지 않는다 — 노출여부 필드만 잠긴다.

**잠금 해제 후 값(공통)**: 판매상태·노출여부의 잠금이 해제되어도 시스템은 두 값을 바꾸지 않는다. 잠금 중 고정된 값(강제 품절·강제 미노출)이 그대로 남으며, 판매중·노출로의 전환은 가맹점(도매는 공급자)이 직접 한다. 노출여부와 판매상태는 서로 영향을 주지 않는다. 해제 조건은 다음과 같다 — 보유수량이 다시 생김(도매주문상품 재구매, 내도매상품 공급자 증량, 내소매상품 보유수량 재입력), 판매가능수량을 다시 올림, 도매 가용재고가 다시 생김(보유수량 증량 또는 판매가능수량 감소), 픽업가능기간을 미래 날짜로 수정함. 판매가능수량은 보유수량이 채워졌다고 자동으로 채우거나 복원하지 않으며 기존 값을 유지한다(판매가능수량이 0이면 위 표의 자동 품절 규칙을 따른다). 소매 취소·반품 승인 시 재고 반영으로 판매가능수량이 복원되어도 판매상태는 자동으로 판매중이 되지 않는다.

### 4-2. 도매 판매상태

| 조건 | 판매상태 | 사용자 조작 |
| --- | --- | --- |
| 보유수량 0 | 강제 품절 | 잠금, 수정 불가 |
| 보유수량 > 0, 보유수량 ≤ 판매가능수량(도매 가용재고 소진) | 강제 품절 | 잠금, 수정 불가 |
| 보유수량 > 판매가능수량(도매 가용재고 존재) | 공급자가 지정한 값 | 자유 전환 — 도매상품수정 화면에서 판매중/품절 직접 선택 가능 |

도매상품에는 픽업가능기간 개념이 없으므로 픽업가능종료일 경과 잠금은 도매 판매상태에 해당하지 않는다. 잠금이 해제되어도 판매상태는 품절로 유지되며 공급자가 직접 전환한다(4-1절 "잠금 해제 후 값(공통)").

### 4-3. 계정 상태·권한 변경에 따른 일괄 품절·미노출

가맹점 이용상태 또는 도매공급권한이 바뀌는 시점에 시스템이 해당 계정의 상품을 일괄 처리한다. 상품별 잠금 조건(4-1, 4-2절)과 별개의 처리다.

| 계기 | 대상 | 처리 |
| --- | --- | --- |
| 이용불가 전환 | 해당 가맹점이 등록한 도매상품(내도매상품)과 소매정보 전체(내도매상품·도매주문상품·내소매상품) | 판매상태 품절, 노출여부 미노출로 즉시 일괄 변경 |
| 도매공급권한 회수 | 해당 가맹점이 등록한 도매상품(내도매상품)만 | 도매판매상태 품절, 도매노출여부 미노출로 즉시 일괄 변경. 소매정보는 변경하지 않는다 |
| 이용제한 전환 | 없음 | 상품 상태를 바꾸지 않는다. 판매 행위 범위는 `09SCM관리자_로그인_정책정리안`을 따른다 |

- 보유수량, 판매가능수량 등 수량은 바꾸지 않는다.
- 일괄 처리로 소매노출여부가 미노출이 된 상품은 메인상품진열에서 자동 삭제한다(12-2절).
- 일괄 처리는 잠금이 아니다. 재고가 있는 상품의 판매상태·노출여부는 이후 가맹점(도매는 공급자)이 상품별로 직접 판매중·노출로 바꿀 수 있다.
- 이용불가 해제, 이용승인, 도매공급권한 재부여 시 시스템은 상품 상태를 되돌리지 않는다. 가맹점이 상품별로 직접 바꾼다.
- 이용불가 가맹점의 소매몰은 접근제한 화면으로 바뀌어 신규 주문을 받지 않는다. 일괄 처리는 상품 상태를 함께 정리하는 처리다.
- 처리 규칙의 기준은 `09SCM관리자_가맹점이용상태이용료정기결제_정책정리안`(2-6, 2-11절)이다.

### 4-4. 설계 의도

소매의 "판매가능수량 0 → 잠금" 원칙을 도매에도 동일하게 적용하되, 도매는 "판매가능수량" 대신 "보유수량 − 판매가능수량(도매 가용재고)"을 기준으로 삼는다. 소매정보가 없는 도매상품은 판매가능수량이 0이므로, 보유수량이 0이 아닌 한 항상 자유 전환 가능하다. 도매 구매자의 주문 수량 상한도 이 도매 가용재고다(구매자 화면 표기는 "주문가능수량", `09SCM관리자_도매주문처리_정책정리안` 참조).

## 5. 노출여부 정책

**원칙**: 노출여부 잠금은 다른 소스의 재고에 종속되어 파생된 소매정보에만 적용한다. 자체 재고를 직접 소유·관리하는 상품(도매상품, 내소매상품)은 화면 접근 자체는 막지 않되, 재고가 없는 상태에서 노출·판매중으로 둘 수는 없으므로 해당 필드는 자동으로 잠근다. 이와 별개로, 픽업가능종료일 경과는 상품출처와 무관하게 소매노출여부를 강제로 잠그는 독립 조건이다.

| 구분 | 잠금 조건 | 사유 |
| --- | --- | --- |
| 도매노출여부 | 잠금 없음 — 보유수량이 0이어도 자유롭게 노출/미노출 전환 | 도매상품은 자체 재고를 직접 보유하는 원천 엔티티다 |
| 소매노출여부(내도매상품·도매주문상품) | 보유수량 0(재고소진) 시 강제 미노출 잠금, 화면 전체가 조회 전용으로 전환 | 도매 보유수량에 연동되어 있어, 연동 재고가 소진되면 노출을 강제로 꺼야 하고 스스로 재고를 늘릴 수도 없다 |
| 소매노출여부(내소매상품) | 보유수량 0 시 노출여부 필드는 강제 미노출로 잠기지만, 조회·수정 화면 진입 자체는 막지 않는다 | 자체 보유수량을 직접 입력·관리하는 상품이므로 도매상품과 같은 논리를 적용한다 — 재고가 없으면 노출은 잠그되, 보유수량을 다시 입력해 스스로 재고를 복구할 수 있어야 하므로 화면 자체를 잠그지 않는다 |
| 소매노출여부(픽업가능종료일 경과) | 수령방식이 픽업 또는 픽업+배달인 소매정보는 픽업가능종료일이 지나면 상품출처와 무관하게 노출여부가 강제 미노출로 잠긴다. 판매상태는 잠기지 않는다. 화면 접근은 막지 않는다 | 픽업 기간이 끝난 상품을 계속 노출 상태로 둘 수 없기 때문이다. 재고가 남아 있는 상품을 품절로 표시하지는 않는다. 보유수량 잠금과 달리 세 가지 상품출처 모두에 동일하게 적용되는 독립 조건이다 |

소매노출여부가 미노출이 되는 모든 경우(재고소진·픽업가능종료일 경과·수동 미노출·이용불가 전환에 따른 일괄 미노출) 해당 상품이 메인상품진열에 있으면 진열에서 자동 삭제한다(12절).

## 6. 상품목록 — 버튼 노출 정책

| # | 조건 | 판매상태 | 노출여부 | 노출 버튼 |

| 1 | 보유수량 있음, 소매정보 없음 | 없음 | 미노출 | 소매정보등록(삭제할 소매정보가 없으므로 삭제·체크박스 없음) |

| 4 | 보유수량 0, 소매정보 없음 | 없음 | 미노출 | 버튼 없음(등록 자체가 불가능) |

내소매상품(상품출처=내소매상품) 건은 보유수량이 있고 로그인 계정이 도매공급권한을 보유한 경우(본사 포함)에만 [도매상품전환] 버튼이 추가로 노출된다. 도매공급권한이 없는 계정에는 노출하지 않으며, 이용제한 상태에서는 버튼을 비활성화한다.

픽업가능종료일 경과는 이 표의 버튼 노출 여부에 영향을 주지 않는다. 보유수량이 있는 한 노출여부가 강제 미노출로 표시되더라도 [상세보기]/[수정]/[삭제] 버튼은 그대로 노출되며, 수정 화면에 진입했을 때 노출여부 필드만 잠긴다(4-1절).

도매 상품목록은 이런 조건 분기가 없다. 보유수량과 무관하게 상세보기/수정/삭제 버튼이 항상 함께 노출되며, 재고소진 시에도 수정 화면에는 진입할 수 있고 그 안에서 판매상태 필드만 잠긴다(4-2절).

도매 상품목록의 "소매정보여부"는 [등록][노출] / [등록][미노출] / [미등록] 중 하나로 표시한다. [등록]은 해당 도매상품에 연결된 소매정보가 있음을, [노출]/[미노출]은 그 소매정보의 소매노출여부(잠금 반영)를 뜻한다.

## 7. 화면 접근 범위 비교 — 재고소진·픽업기간 경과 시

| 구분 | 동작 | 근거 |
| --- | --- | --- |
| 소매정보(내도매상품·도매주문상품), 보유수량 0 | 목록에서 상세보기·삭제만 노출, 상세 화면은 전체 조회 전용으로 전환된다(삭제만 가능) | 재고소진 시 노출여부가 강제 미노출로 잠기고, 다른 소스(도매)의 재고에 종속되어 있어 스스로 재고를 늘릴 수 없다 |
| 소매정보(내소매상품), 보유수량 0 | 목록에서 상세보기·수정·삭제가 그대로 노출되고 수정 화면에 진입할 수 있다. 판매상태·노출여부 필드만 잠기고 보유수량 등 나머지 필드는 계속 자유롭게 수정 가능하다 | 도매 연동 없이 자체 보유수량을 직접 입력·관리하는 상품이므로 도매상품과 동일하게 스스로 재고를 복구할 수 있는 주체다 |
| 소매정보(픽업가능종료일 경과, 보유수량 있음) — 상품출처 공통 | 목록에서 상세보기·수정·삭제가 그대로 노출되고 수정 화면에 진입할 수 있다. 노출여부 필드만 잠기고 판매상태와 보유수량을 포함한 나머지 필드는 계속 자유롭게 수정 가능하다 | 픽업 기간이 끝난 상품이라도 화면 자체를 막을 이유는 없으며, 판매자가 픽업가능기간을 다시 설정해 재노출할 수 있어야 한다 |

## 8. 신규 등록 시 초기값 정책

**원칙**: 등록 시점에 입력한 수량(보유수량 또는 판매가능수량)을 기준으로 판매상태를 자동 산정한다 — 0이면 품절, 0 초과면 판매중으로 자동 생성되며, 별도로 판매상태를 선택하는 입력 단계는 없다. 등록 이후에는 도매상품수정/소매정보수정 화면에서 4절 조건에 따라 자유롭게 전환할 수 있다.

| 화면 | 판매상태 필드 노출 | 초기값 산정 규칙 |
| --- | --- | --- |
| 도매상품등록 | 필드 없음 | 보유수량 0 → 품절, 0 초과 → 판매중. 보유수량 0으로 등록하는 것도 유효한 입력이다 |
| 소매정보등록(내도매상품·도매주문상품, 신규) | 필드 없음 | 판매가능수량 0 → 품절, 0 초과 → 판매중 |
| 소매상품등록(내소매상품, 신규) | 필드 없음 | 보유수량 0 → 품절, 0 초과 → 판매중 |
| 도매상품수정 / 소매상품수정 | 필드 있음(조건부 잠금) | 4-1, 4-2절 기준을 그대로 적용 |

### 8-1. 수령방식 초기값

상품 신규 등록 시 수령방식 초기값은 소매설정(`09SCM관리자_소매몰설정_정책정리안` 2-4절)의 기본 수령방식을 따른다. 적용 화면은 수령방식을 입력하는 신규 등록 화면인 도매상품등록(내 소매몰 등록 입력 영역), 소매정보등록, 소매상품등록이다.

| 소매설정 기본 수령방식(몰 기본값) | 상품 수령방식 초기값 |
| --- | --- |
| 픽업만 | 픽업 |
| 배달만 | 배달 |
| 픽업, 배달 모두 | 픽업+배달 |

- 초기값은 상품별로 변경할 수 있다.
- 이미 등록된 상품의 수령방식에는 영향이 없다. 소매설정의 기본 수령방식을 바꿔도 기존 상품은 바뀌지 않는다.
- 소매설정의 표기(픽업만/배달만/픽업, 배달 모두)는 몰 단위 기본값이고, 상품의 표기(픽업/배달/픽업+배달)는 상품 단위 값이다. 둘은 위 표의 대응 관계로 연결된다.

### 8-2. 우리지역 등록 지역의 초기값과 입력 규칙

공급범위가 우리지역인 도매상품을 노출할 지역을 정한다. 도매상품등록·도매상품수정·도매상품전환과 도매설정에 공통 적용하며, 입력 영역의 필드 제목은 모두 "우리지역"이다(도매설정의 섹션 제목은 "공급범위(우리지역) 설정"). 구매자 노출 판정은 `09SCM관리자_도매주문처리_정책정리안` 2-1절을 따른다.

| 항목 | 내용 |
| --- | --- |
| 적용 조건 | 공급범위가 우리지역일 때만 입력 영역을 노출한다. 전국·우리본사이면 노출하지 않으며, 저장 시 공급범위가 우리지역이 아니면 추가한 지역은 저장하지 않는다 |
| 지역 단위 | 시·도 + 시·군·구. 시 아래에 일반구가 있으면 시와 구를 한 단위로 본다. "경기 수원시 영통구" 형식으로 표시하며 "전체" 선택은 없다 |
| 기본 지역 | 공급자 사업장 주소의 시·군·구. 삭제할 수 없다. 현재 사업장 주소에서 산출하므로 저장하는 값은 추가한 지역뿐이며, 사업장 주소가 바뀌면 기본 지역도 바뀐 주소 기준으로 적용한다 |
| 등록 한도 | 기본 지역을 포함해 상품당 최대 50곳. 중복 등록은 할 수 없다. 한도에 도달하면 [지역 추가]를 비활성화한다 |
| 입력 방식 | [지역 추가] 팝업에서 시·도, 시·군·구를 차례로 선택해 추가한다. 추가한 지역은 칩으로 표시하며 ×로 삭제한다. 기본 지역은 "(기본)"으로 표시하며 삭제 버튼을 두지 않는다. [지역 추가] 옆에 "등록 N/50곳"을 표시한다 |
| 영역 구성 | 필드 제목 → 안내 문구 → [지역 추가]와 등록 수 → 지역 칩 순서다. 도매상품등록·수정·전환 화면은 공급범위 옆 칸에 배치하며 공급범위가 우리지역이 아니면 빈 칸으로 둔다 |
| 안내 문구(공통) | "본사 구분 없이, 등록한 우리지역(시·군·구 단위)에 사업장 주소가 있는 모든 가맹점에 노출됩니다. 최대 50곳까지 등록할 수 있습니다." 모든 화면에서 같은 문구를 쓴다 |
| 도매설정의 등록 지역 | 도매설정의 "공급범위(우리지역) 설정"은 신규 도매상품 등록·도매상품전환의 초기값이다. 등록·전환 화면에 진입할 때 도매설정의 추가 지역을 복사하며, 이후 도매설정을 바꿔도 이미 등록된 상품의 등록 지역은 바뀌지 않는다. 필수 입력이 아니며 등록하지 않아도 저장할 수 있다 |
| 상세 표기 | 도매상품 상세의 공급범위에 "우리지역 (기본 지역 외 N곳)"을 표기하고, 추가한 지역이 있으면 다음 줄에 " / "로 구분해 나열한다. 괄호 안에는 기본 지역을 표기한다 |
| 구매자 화면 | 공급범위 필터와 표기는 "우리지역"으로만 노출하며 시·군·구 목록은 노출하지 않는다 |

## 9. 삭제 정책

### 9-1. 공통 원칙

| 항목 | 내용 |
| --- | --- |
| 차단 조건 | 없음. 진행중 주문이 있어도 삭제할 수 있다 |
| 고지 | 확인 창에서 도매·소매 주문 처리 중 혼선이 생길 수 있음과 삭제한 데이터는 복구할 수 없음을 고지한다 |
| 주문내역 | 주문 당시 정보(스냅샷 텍스트)로 그대로 남으며, 주문 진행에는 영향이 없다 |
| 소비자 화면 | 소매몰에서 해당 상품과 연동되던 상품 페이지가 사라진다 |
| 복구 | 삭제한 데이터는 복구할 수 없다 |

### 9-2. 삭제 대상별 의미

| 삭제 대상 | 삭제 결과 |
| --- | --- |
| 내 도매상품(도매관리 > 내 도매상품) | 도매상품이 삭제된다. 연동된 소매정보가 있으면 함께 삭제되고, 소매몰 노출·메인상품진열에서도 제외되며 판매가능수량은 해제된다 |
| 소매정보(상품출처: 내도매상품·도매주문상품) | 소매정보만 삭제되어 소매몰 노출이 해제된다. 원 도매상품과 주문 이력은 유지되며, 상품목록에서 행이 사라지지 않고 소매정보가 없는 상태로 남아 [소매정보등록]이 다시 노출된다. 내도매상품 자체의 삭제는 도매관리 > 내 도매상품에서만 가능하다 |
| 내소매상품 | 상품 자체가 삭제되어 상품목록에서 행이 사라진다 |

소매정보가 없는 행(상품목록의 [소매정보등록] 행)은 삭제할 대상이 없으므로 [삭제] 버튼과 일괄삭제 체크박스를 노출하지 않는다.

상품 삭제 확인 창은 도매상품·소매정보·내소매상품 모두 아래 구성을 동일하게 사용한다. 마지막 문장은 회원·가맹점 등 모든 삭제 확인 창과 동일한 "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요."이다.

| 구분 | 문구 |
| --- | --- |
| 단건 | "상품을 삭제하시겠습니까?" / (소매정보가 연동된 상품일 때만) "소매정보가 연동된 상품입니다." / "삭제 시 도매·소매 주문 처리 중 혼선이 생길 수 있습니다." / "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요." |
| 일괄 | "선택한 N건을 삭제하시겠습니까?" / (연동 상품이 포함될 때만) "소매정보가 연동된 상품이 포함되어 있습니다." / 이하 동일 |

## 10. 상품목록 검색·필터

- 공통: 검색어는 대소문자를 구분하지 않으며, 하이픈(-)은 무시하고 매칭한다(예: 사업자번호·휴대폰번호). 검색창 안내문구(플레이스홀더)는 실제 검색 대상을 쉼표로 나열한다.
- 도매관리 > 내 도매상품: 필터는 공급범위·도매판매상태·도매노출여부·1차 카테고리·2차 카테고리이며, 검색("상품코드, 상품명 검색")을 지원한다.
- 소매관리 > 상품관리 > 상품목록: 필터는 상품출처·소매판매상태·소매노출여부·채팅주문여부·1차 카테고리·2차 카테고리이며, 검색("상품코드, 상품명 검색")과 "보유수량 있는 상품만 보기" 체크박스를 지원한다.
- 상품코드는 도매·소매 구분 없는 단일 체계("P" + 4자리 숫자, 2-2절)이므로 상품코드 검색은 상품출처와 무관하게 같은 방식으로 동작한다. 도매 상품과 소매 상품의 구분은 상품코드가 아니라 상품출처 필터로 한다.
- 도매관리 > 도매상품 주문하기: 검색("상품명, 공급자명 검색")을 지원한다. 필터는 공급범위(전체/전국/우리지역/우리본사)와 상품카테고리(1차·2차)이며, 정렬은 최신순/주문순/가격순이다.
- 페이지네이션: 내 도매상품, 도매상품 주문하기, 소매 상품목록 모두 페이지당 20건이며 목록 페이지네이션은 디자인시스템 문서의 "목록 페이지네이션·건수 표시 표준"을 따른다. 내 도매상품·소매 상품목록의 체크박스 선택·전체선택·일괄삭제는 현재 페이지에 한정하며 페이지 이동 시 선택을 해제한다.

## 11. 상품카테고리

### 11-1. 도매 카테고리와 소매 카테고리의 분리

- 도매 카테고리와 소매 카테고리는 서로 분리된 영역이다. 같은 이름의 카테고리를 쓰더라도 서로 연결되거나 동기화되지 않는다.
- 도매 카테고리(1차/2차)는 시스템 고정 영역이다. 모든 계정이 동일한 카테고리를 공통으로 사용하며, 계정 사용자가 추가·수정·삭제·순서 변경할 수 없다. 별도의 도매 카테고리 관리 화면은 없다.
- 소매 카테고리(1차/2차)는 계정(본사·가맹점) 사용자가 직접 관리한다. 신규 가맹점은 소매 카테고리가 하나도 없는 빈 상태로 시작한다.
- 도매상품과 소매정보는 카테고리를 각각 따로 선택·저장한다. 소매정보를 등록할 때 도매상품의 카테고리를 소매 카테고리로 자동 적용하지 않으며, 소매정보가 아직 등록되지 않은 상품은 소매 카테고리가 없는 것으로 보아 소매 상품목록의 카테고리 컬럼에 "-"로 표시하고 카테고리 필터 결과에서 제외한다.
- 소매정보 등록·수정에서 소매 카테고리 1차는 필수, 2차는 선택("선택 안 함")이다. 소매 카테고리가 하나도 없으면 선택할 1차 카테고리가 없으므로 소매 상품카테고리를 먼저 등록해야 한다.

### 11-2. 소매 상품카테고리 화면

위치: 소매관리 > 상품관리 > 상품카테고리

- 1차 카테고리를 선택하면 해당 1차에 속한 2차 카테고리가 표시된다. 1차 카테고리가 없으면 "1차 카테고리를 먼저 등록해주세요.", 선택한 1차에 2차가 없으면 "등록된 2차 카테고리가 없습니다."를 안내한다.
- 각 카테고리에는 카테고리명과 "연동상품 N"(해당 카테고리를 소매 카테고리로 지정한 소매정보 건수)을 표시한다. 1차 카테고리의 연동상품 수는 하위 2차의 합계다.
- 추가: 각 영역의 [+ 추가]로 입력 행을 열어 카테고리명을 입력하고 [저장]한다. 2차 카테고리는 선택된 1차 아래에만 추가할 수 있어 1차가 없으면 [+ 추가]가 비활성화된다. 카테고리명이 비어 있으면 저장되지 않는다.
- 수정: [수정]으로 카테고리명을 바꾸고 [저장] 또는 [취소]한다.
- 삭제: 연동상품이 1건 이상인 카테고리는 [삭제]가 비활성화된다("연동상품이 있어 삭제할 수 없습니다"). 삭제 시 확인 창을 거치며, 하위 2차가 있는 1차를 삭제하면 "하위 2차 카테고리도 함께 삭제됩니다."를 함께 고지한다. 확인 창의 마지막 문장은 "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요."로 다른 삭제 확인 창과 같다.
- 순서 변경: 카테고리를 드래그해 1차끼리, 같은 1차 안의 2차끼리 순서를 바꾼다. 변경한 순서는 즉시 반영되며 소매정보 등록·수정과 소매 상품목록 필터의 카테고리 선택 목록 순서에 그대로 쓰인다.

### 11-3. 카테고리를 사용하는 화면

| 구분 | 사용 화면 |
| --- | --- |
| 도매 카테고리(시스템 고정) | 도매상품 등록·수정, 도매상품전환(도매정보 입력), 내 도매상품 목록 필터·컬럼·상세, 도매상품 주문하기 필터·카드·상세 |
| 소매 카테고리(계정별 관리) | 소매정보 등록·수정, 소매상품 등록, 소매 상품목록 필터·컬럼, 소매정보 상세 |

## 12. 메인상품진열

위치: 소매관리 > 상품관리 > 메인상품진열. 소매몰 메인 화면에 노출할 소매상품을 고르고 진열 순서를 정한다.

### 12-1. 후보 목록

- 후보 목록(전체 소매상품)은 소매몰에 현재 노출 중인 소매상품만 대상으로 한다. 소매정보가 없는 상품은 노출여부가 없으므로 대상이 아니다.
- 후보 목록에는 "소매몰에 노출 중인 상품만 표시됩니다." 안내를 둔다.
- 판매상태가 품절이어도 노출 중이면 후보·진열 대상이며, 품절 상태로 진열이 유지된다.
- 보유수량 0은 품절 + 미노출(미노출 우선)이므로 후보·진열에서 제외된다.
- 노출/미노출 구분은 표시하지 않고 품절 여부만 표시한다.

### 12-2. 진열 자동 삭제

- 소매노출여부가 미노출이 되는 모든 경우(픽업가능종료일 경과, 수동 미노출, 재고소진, 이용불가 전환에 따른 일괄 미노출 등) 진열 중인 상품은 메인상품진열에서 자동 삭제한다.
- 이후 다시 노출해도 진열에는 자동으로 복귀하지 않으며, 직접 다시 추가해야 한다.
- 소매정보가 삭제되면(내 도매상품·내소매상품 삭제 포함) 진열에서도 제외된다(9-2절).

### 12-3. 진열 순서와 저장

- 노출 순서가 곧 진열 순서이며, 드래그로 변경한다.
- 추가·제외·순서 변경은 [저장] 시에만 반영된다. 저장하지 않고 화면을 이탈하면 반영되지 않는다.

### 13-1. 필드별 검증

## 14. 확인 필요 사항

| 항목 | 내용 |
