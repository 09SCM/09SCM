# 1장. 도매 주문 처리·도매매출조회 (W-ORD)

## 1.1 적용 범위

- 대상 화면: 도매관리 > 도매상품 주문하기(구매), 장바구니, 주문서 작성, 주문내역(구매자), 주문접수관리(공급자), 도매설정(배송방식·카드결제 수수료·우리지역 설정), 도매매출조회
- 대상 계정: 도매 거래의 공급자 또는 구매자인 본사·가맹점 계정. 도매매출조회는 도매공급권한을 보유한 계정만 접근한다
- 제외 범위: 도매상품 등록·수정·판매상태·노출여부(→ 2장 W-PRD), 도매공급권한 회수·이용불가 전환 시 상품 일괄 처리(→ 02 파일 A-FEE), 알림 발송 기준(→ 02 파일 A-NTF)
- 결제내역 메뉴는 두지 않는다. 결제확인·배송확정·취소·반품 처리를 모두 주문접수관리·주문내역에서 하기 때문이다

## 1.2 정의

| 용어 | 정의 |
| --- | --- |
| 공급자 / 구매자 | 도매상품을 파는 계정 / 사는 계정 |
| 공급범위 | 공급자가 도매상품을 노출할 구매자의 범위. 전국 / 우리지역 / 우리본사 |
| 등록 지역 | 공급범위가 우리지역인 도매상품을 노출할 시·군·구 목록. 기본 지역(공급자 사업장 주소의 시·군·구)과 상품별로 추가한 지역으로 구성한다 |
| 구매불가 | 장바구니 품목이 공급범위 변경 등으로 구매자에게 더 이상 노출되지 않아 주문할 수 없는 상태 |
| 주문서 | 단일 공급자의 품목만으로 구성되는 주문 1건. 주문번호 1개를 가진다 |
| 도매 가용재고 | 구매자가 한 번에 주문할 수 있는 수량의 상한. 구매자 화면(상품상세 하단 바)에서는 "주문가능수량"으로 표기한다 |
| 처리시점 | 처리상태가 가장 최근에 전환된 일시 |
| 자동 배송확정 | 배송중 전환 후 7일이 지나 시스템이 처리하는 배송확정 |
| 조정 모드 | 구매자 요청이 있는 건을 승인 또는 반려로 처리하는 방식 |
| 직권 모드 | 요청 이력이 없거나 반려로 종료된 건을 공급자가 바로 처리하는 방식 |
| 구매자 즉시취소 | 주문접수 단계에서 구매자가 카드결제 건 또는 결제대기 건을 승인 없이 직접 취소하는 처리 |
| 총 결제금액 | 상품금액 합계 + 배송비 + 구매자부담 카드수수료 |

처리상태(도매), 결제상태, 취소·반품 상태, 환불구분, 기준일시, 도매 가용재고, 상품코드는 00 공통 3-3~3-5를 따른다.

## 1.3 요건

### 가. 노출·구매 제한·장바구니

| ID | 요건명 | 요건 |
| --- | --- | --- |
| W-ORD-001 | 공급범위별 구매자 노출 | 도매상품은 공급범위에 따라 구매자의 도매상품 주문하기 목록에 노출한다. 전국은 모든 구매자, 우리지역은 상품의 등록 지역에 사업장 주소가 있는 구매자(→ W-ORD-073 우리지역 노출 판정), 우리본사는 같은 본사 소속 가맹점에게 노출한다 |
| W-ORD-073 | 우리지역 노출 판정 | 우리지역 상품은 구매자 사업장 주소의 시·군·구가 상품의 등록 지역(기본 지역 + 추가한 지역)에 포함될 때 노출한다. 시 아래에 일반구가 있는 지역은 시와 구를 한 단위로 본다. 본사 소속 여부는 판정에 쓰지 않는다. 구매자 화면의 공급범위 필터와 상품 표기는 "우리지역"으로만 표시하고 시·군·구 목록은 노출하지 않는다 (→ OI-W-06) |
| W-ORD-074 | 공급자 본인 상품의 노출 | 공급자 본인의 상품은 공급범위와 관계없이 본인의 도매상품 주문하기 목록에 노출한다 (→ W-ORD-004 본인 상품의 화면 표시) |
| W-ORD-075 | 공급범위 변경과 기존 주문 | 공급범위·등록 지역을 변경해도 이미 생성된 주문과 진행 중인 주문은 영향을 받지 않는다 |
| W-ORD-002 | 구매 계정의 식별 | 도매 구매자는 구매 계정의 아이디로 연결한다. 아이디는 가입 후 변경할 수 없다. 도매 주문 품목은 상품코드로 표시한다 |
| W-ORD-003 | 공급자 본인 상품 구매 차단 | 상품의 판매자가 로그인 계정 본인이면 장바구니 담기와 바로구매를 할 수 없다. 구매 버튼을 노출하지 않으며, 주문 생성 단계에서도 같은 조건을 다시 검증해 화면 요소를 우회한 주문 생성을 차단한다 (→ OI-W-01) |
| W-ORD-004 | 본인 상품의 화면 표시 | 목록·상세에 "내 상품" 배지를 노출한다. 상세에는 구매 버튼 대신 구매 불가 안내만 표시한다 |
| W-ORD-005 | 주문서의 공급자 단일 구성 | 장바구니에는 여러 공급자의 상품을 담을 수 있다. 주문서는 항상 단일 공급자 품목으로만 구성하며 주문번호 1개를 부여한다. 장바구니는 공급자별로 그룹으로 표시하고 그룹 단위로 주문서를 작성한다 |
| W-ORD-006 | 바로구매 | 상품상세의 바로구매는 장바구니를 거치지 않고 해당 공급자 1건짜리 주문서로 이동한다 |
| W-ORD-007 | 수량 변경 시점 | 주문서 작성 화면에서는 품목 수량을 변경할 수 없다. 수량 변경은 장바구니 화면에서만 한다 |
| W-ORD-008 | 도매 가용재고 기준 수량 상한 | 구매자의 주문 수량 상한은 도매 가용재고(보유수량 − 소매 판매가능수량)다. 상품상세 하단 바에는 "주문가능수량 N개"로 표기한다. 소매에 배정된 판매가능수량은 도매 구매자가 주문할 수 없다. 상품상세·장바구니의 수량 증가는 도매 가용재고를 넘을 수 없다 |
| W-ORD-009 | 도매 가용재고 0의 품절 표시 | 도매 가용재고가 0이면 해당 상품을 품절로 표시한다. 도매판매상태가 품절인 상품도 같다 |
| W-ORD-010 | 장바구니 품절 품목의 주문 제한 | 장바구니 품목의 도매판매상태가 품절이거나 도매 가용재고가 0이면 해당 품목에 [품절] 뱃지를 표시한다. 그룹에 품절 품목이 있으면 그 그룹의 [전체주문]을 비활성화하고, 선택한 품목에 품절이 포함되면 [선택상품주문]을 비활성화한다. 다른 공급자 그룹의 주문 버튼에는 영향이 없다 |
| W-ORD-011 | 주문 생성 시점 재검증 | 주문 생성(주문 완료) 시점에 품목별 재고와 노출 상태를 다시 검증한다. 품절 품목이 있으면 "품절상품이 존재합니다.", 구매불가 품목이 있으면 "구매불가 상품이 존재합니다.", 품절·구매불가는 아니지만 주문 수량이 도매 가용재고를 초과하는 품목이 있으면 "재고가 부족한 상품이 있습니다."를 안내하고 주문을 생성하지 않는다. 여러 경우가 겹치면 품절 → 구매불가 → 재고 부족 순으로 하나의 문구만 안내한다. 재고 부족은 장바구니에 뱃지로 표시하지 않는다 |
| W-ORD-076 | 장바구니 구매불가 품목의 표시 | 장바구니 품목이 공급범위·등록 지역 변경 또는 구매자 사업장 주소 변경으로 구매자에게 더 이상 노출되지 않으면(도매노출여부는 노출 상태) 해당 품목에 [구매불가] 뱃지와 "공급범위가 변경되어 구매할 수 없습니다."를 표시한다. [품절]과 [구매불가]는 한 품목에 함께 표시할 수 있으며 상품명 아래 줄에 표시한다 |
| W-ORD-077 | 장바구니 구매불가 품목의 주문 제한 | 그룹에 구매불가 품목이 있으면 그 그룹의 [전체주문]을 비활성화하고, 선택한 품목에 구매불가가 포함되면 [선택상품주문]을 비활성화한다. 다른 공급자 그룹의 주문 버튼에는 영향이 없다. 해당 품목을 삭제하거나 선택에서 제외하면 나머지 품목은 주문할 수 있다. 그룹 하단에 별도 안내 문구는 두지 않는다 |
| W-ORD-078 | 장바구니 미노출·삭제 품목의 제거 | 도매노출여부가 미노출이 되거나 삭제된 상품은 장바구니를 조회하는 시점에 구매불가 안내 없이 장바구니에서 제거한다. 품절과 미노출이 동시에 걸린 상품은 미노출 기준으로 제거한다 |
| W-ORD-012 | 장바구니 금액 요약 | 그룹 하단에 선택상품금액, 전체상품금액, 배송비, 총 주문금액을 이 순서로 표기한다. 총 주문금액은 선택상품금액에 배송비를 더한 값이다. 무료배송·착불의 배송비는 0원이다. 선택한 품목이 없으면 선택상품금액과 총 주문금액은 0원이고 배송비를 더하지 않는다 |
| W-ORD-013 | 주문 완료 품목의 장바구니 제거 | [선택상품주문]은 그룹에서 선택한 품목만, [전체주문]은 그룹의 품목 전체를 주문서로 전달한다. 주문이 완료된 품목만 장바구니에서 제거한다 |
| W-ORD-079 | 장바구니 건수의 기준 | 장바구니 건수 N은 장바구니에 담긴 품목(상품코드)의 수이며 주문 수량의 합계가 아니다. 같은 상품을 다시 담으면 품목은 늘지 않고 기존 품목의 수량만 늘어난다. 도매상품 주문하기 상단의 [장바구니 (N)] 버튼과 장바구니의 `전체 N건`은 같은 기준을 쓰며, 장바구니가 비어 있으면 버튼에 건수를 표기하지 않는다. 미노출·삭제로 제거되는 품목은 건수에 포함하지 않는다 (→ W-ORD-078) |
| W-ORD-080 | 주문서 작성 화면의 초기값 | 주문자 정보의 상호명은 구매 계정의 사업자 정보 상호명이며 조회 전용이다. 이름·휴대폰번호·이메일의 초기값은 구매 계정의 회원정보에 등록된 값이며, 주문서에서 수정할 수 있다. 수정한 값은 해당 주문에만 저장하고 회원정보는 바뀌지 않는다. 배송지는 `등록된 사업장 주소`(기본 선택)와 `직접입력` 중에서 고른다. `등록된 사업장 주소`는 구매 계정의 사업자 정보에 등록된 사업장 주소이며 조회 전용이다. `직접입력`은 우편번호 검색으로 기본주소를 채우고 상세주소를 입력한다. 계좌이체의 입금자명 초기값은 구매 계정의 회원정보 > 계좌정보에 등록된 예금주명이며 주문서에서 수정할 수 있다 (→ W-ORD-014) |

### 나. 결제 수단·금액 구성

| ID | 요건명 | 요건 |
| --- | --- | --- |
| W-ORD-014 | 결제수단별 생성 시 결제상태 | 카드결제는 결제완료로, 계좌이체는 결제대기로 주문을 생성한다. 계좌이체는 입금자명을 필수로 입력하며 초기값은 구매 계정의 회원정보 > 계좌정보에 등록된 예금주명이다(→ W-ORD-080). 공급자가 결제확인을 처리해야 결제완료로 전환한다 |
| W-ORD-015 | 배송방식 설정 단위 | 배송방식은 상품이 아니라 공급자 1명당 1개만 설정한다. 도매설정 화면에서 무료배송 / 기본배송비(금액 직접 입력) / 착불 중 하나를 선택한다. 설정값은 그 공급자의 모든 도매상품에 예외 없이 적용한다. 기본배송비 금액을 입력하지 않으면 0으로 저장한다 |
| W-ORD-016 | 배송비 산정 | 기본배송비는 주문 건당 설정 금액을 1회 가산한다. 무료배송과 착불은 결제금액에 배송비를 0원으로 반영한다. 착불은 배송 시 택배사에 별도로 지불한다 |
| W-ORD-017 | 배송비의 주문 스냅샷 | 주문 생성 시점의 배송방식과 배송비 금액을 주문에 저장한다. 이후 공급자가 설정을 바꿔도 이미 생성한 주문의 배송비 표기와 금액은 바뀌지 않는다 |
| W-ORD-018 | 카드결제 수수료 설정 | 공급자별로 카드결제 수수료 부담 주체(구매자부담 / 공급자부담)를 도매설정에서 설정한다. 수수료율(%)은 구매자부담일 때만 입력하며 입력하지 않으면 0으로 저장한다 |
| W-ORD-019 | 카드결제 수수료의 결제금액 반영 | 결제수단이 카드결제이고 공급자 설정이 구매자부담이면 (상품금액 + 배송비) × 수수료율을 결제금액에 더한다. 계산 결과는 소수점 이하를 반올림한 원 단위다. 계좌이체와 공급자부담 설정은 구매자 결제금액에 반영하지 않는다 |
| W-ORD-020 | 카드결제 수수료의 주문 스냅샷 | 주문 생성 시점의 부담 주체, 수수료율, 수수료 금액을 주문에 저장한다. 이후 설정을 바꿔도 이미 생성한 주문의 수수료 표기와 금액은 바뀌지 않는다 |
| W-ORD-021 | 최종 결제금액 산식 | 결제금액은 상품금액 합계 + 배송비 + 카드수수료(구매자부담이며 카드결제일 때만)다 |
| W-ORD-022 | 도매설정 입력 범위 | 도매설정에는 필수 입력 항목이 없다. 기본배송비는 0원 이상의 정수, 수수료율은 0 이상 100 미만의 수로 입력한다. 범위를 벗어나면 저장하지 않는다 |
| W-ORD-023 | 공급자부담 수수료의 정산 범위 | 공급자부담 수수료는 결제금액에 포함된 PG 수수료다. 정산은 PayApp에서 처리하며 이 시스템의 관리 범위가 아니다 |

| W-ORD-032 | 결제확인 | 결제확인은 결제대기 건을 결제완료로 전환하는 조작이다. 계좌이체·카드결제 어느 쪽이든 같은 조작을 쓴다. 결제상태만 바꾸며 처리상태는 바꾸지 않는다 |
| W-ORD-033 | 결제상태 표기 | 주문상세 결제상태는 `[상태] 일시` 형식이다. 결제대기는 일시 없이 `[결제대기]`, 결제완료는 `[결제완료] 결제완료 일시`, 결제대기에서 취소된 건은 `[결제취소] 취소·반품 승인 일시`, 환불이 있는 결제취소는 `[결제취소] 전체환불|부분환불 취소·반품 승인 일시 (결제완료 일시 결제완료)`로 표기한다. 결제취소 건의 환불구분은 목록과 상세에 표시하되, 결제대기에서 취소된 건은 환불이 없으므로 표시하지 않는다 |

### 라. 처리상태 전이

| ID | 요건명 | 요건 |
| --- | --- | --- |
| W-ORD-034 | 처리상태의 진행 순서 | 처리상태는 주문접수 → 배송대기 → 배송중 → 배송확정 순서로 진행한다. 다음단계 버튼은 한 단계씩만 진행하며 단계를 건너뛸 수 없다. 배송확정은 배송중 단계에서 확인 팝업을 거쳐 처리한다 |
| W-ORD-035 | 단계별 구매자·공급자 조작 범위 | 주문접수는 구매자 즉시취소·취소요청, 공급자 배송대기 처리·취소처리가 가능하다. 배송대기는 구매자 조회만, 공급자 배송중 처리·되돌리기·취소처리가 가능하다. 배송중은 구매자 반품요청·배송확정, 공급자 되돌리기·반품처리·배송확정이 가능하다. 배송확정은 양쪽 모두 조작할 수 없다 |
| W-ORD-036 | 되돌리기 | 되돌리기는 직전 단계로만 복귀한다(배송대기 → 주문접수, 배송중 → 배송대기). 확인 팝업 없이 즉시 반영하며 처리시점을 되돌린 시점으로 갱신한다. 주문접수, 배송확정, 취소·반품요청, 취소·반품승인 상태에서는 제공하지 않는다 |
| W-ORD-037 | 배송확정의 처리 주체 | 배송확정은 구매자와 공급자 모두 처리할 수 있다. 배송확정 후에는 상태 변경, 취소, 반품을 할 수 없다 |
| W-ORD-038 | 배송확정 시 결제상태 전환 | 배송확정 처리(구매자·공급자 처리, 자동 배송확정) 시점에 결제상태가 결제대기이면 결제완료로 함께 전환한다. 배송확정 이후에는 결제대기 건이 존재하지 않는다 |
| W-ORD-039 | 자동 배송확정 | 처리상태가 배송중으로 전환된 일시(처리시점)로부터 7일이 지나면 시스템이 배송확정한다. 이후에는 반품요청을 할 수 없다. 결제상태가 결제대기이면 결제완료로 함께 전환하며 결제완료 일시는 자동 배송확정 일시로 기록한다 |
| W-ORD-040 | 자동 배송확정 예정일시의 재계산 | 처리시점이 갱신되면 자동 배송확정 예정일시를 다시 계산한다. 배송중에서 다른 단계로 되돌렸다가 다시 배송중으로 전환한 건과 반품요청이 반려되어 배송중으로 복귀한 건은 해당 시점부터 7일을 다시 센다 |
| W-ORD-041 | 자동 배송확정의 알림 | 자동 배송확정 시 구매자와 판매자 모두에게 배송확정 알림을 발송한다 (→ A-NTF-030 자동 배송확정 알림) |
| W-ORD-042 | 처리시점의 갱신 | 다음단계, 일괄변경, 되돌리기, 배송확정(구매자·공급자 처리, 자동 배송확정), 반려 복귀로 처리상태가 바뀔 때마다 처리시점을 갱신한다 |
| W-ORD-043 | 배송확정 상품의 소매정보 대상화 | 배송확정된 주문의 상품은 소매관리 > 상품관리 > 상품목록에서 소매정보등록 대상이 된다. 소매정보는 주문 단위가 아니라 상품(코드) 단위로 만든다. 배송확정 시 구매자의 도매주문상품 보유수량(계정 + 상품코드 단위)이 구매 수량만큼 증가한다 (→ W-PRD 2장의 도매주문상품 소매정보 생성 규칙) |
| W-ORD-044 | 관리 버튼의 노출 조건 | 처리상태별 버튼은 아래 표를 따른다. 버튼 이름은 이동할 단계명을 그대로 쓴다. 취소·반품요청 건은 [취소처리] 또는 [반품처리](조정 모드)만, 취소·반품승인 건은 버튼 없이 "처리 완료된 주문입니다." 안내만 노출한다 |
| W-ORD-045 | 결제확인 버튼의 노출 범위 | 목록의 [결제확인]은 처리상태가 주문접수·배송대기인 결제대기 건에만 노출한다. 배송중 단계의 결제대기 건은 주문상세에서만 [결제확인]을 처리한다 |
| W-ORD-046 | 결제·배송확정 버튼 | 배송중 단계이며 결제상태가 결제대기인 주문의 배송확정 버튼 명칭은 [결제·배송확정]이다. 확인 팝업에서 배송확정과 결제완료 전환을 함께 처리한다 |
| W-ORD-047 | 일괄변경의 대상과 옵션 | 일괄변경은 현재 페이지에서 선택한 건만 대상으로 하며 페이지를 이동하면 선택을 해제한다. 옵션은 배송대기와 배송중뿐이다. 배송확정과 취소·반품처리는 확인 팝업과 사유·환불 입력이 필요하므로 대상에서 제외한다. 결제확인도 대상이 아니다 |
| W-ORD-048 | 일괄변경의 반영 조건 | 선택한 주문 중 배송대기는 처리상태가 주문접수인 건에만, 배송중은 처리상태가 배송대기인 건에만 반영한다. 나머지는 변경 없이 제외한다. 반영 시 처리시점을 기록한다 |

### 마. 취소·반품

| ID | 요건명 | 요건 |

| W-ORD-049 | 구매자 요청 가능 시점 | 즉시취소는 주문접수 단계이고 취소·반품 이력이 없는 카드결제 건 또는 결제대기 건에 한다. 취소요청은 주문접수 단계이고 취소·반품 이력이 없는 계좌이체 결제완료 건에 한다. 반품요청은 배송중 단계이고 취소·반품 이력이 없을 때 배송중 전환 후 7일 이내에만 한다 (→ OI-W-04, OI-W-05) |

| W-ORD-051 | 구매자 환불계좌 입력 | 계좌이체 건의 요청에는 환불은행·예금주·환불계좌번호와 요청 사유를 필수로 입력한다. 카드결제 건은 승인 시 PayApp으로 결제를 취소하므로 환불계좌를 입력받지 않으며 요청 사유만 필수다. 구매자가 입력한 환불계좌는 공급자 처리 화면에 채우되 공급자가 처리 시점에 수정할 수 있다 |
| W-ORD-052 | 구매자 즉시취소의 확정 결과 | 구매자 즉시취소는 공급자 승인 없이 취소승인으로 확정한다. 처리 주체는 "구매자 즉시취소"로 기록하고 처리상태는 비운다. 공급자 주문접수관리에서는 취소·반품승인 그룹에 표시하며 공급자가 처리할 조작은 없다 |
| W-ORD-053 | 즉시취소의 재고·결제 처리 | 즉시취소 시 공급자 보유수량을 복원한다. 재고 반영 체크박스는 두지 않는다. 카드결제 건은 결제를 전액 취소(총환불금액 = 총 결제금액)해 결제취소로 전환하고, 결제대기 건은 환불 없이 결제취소로 전환한다 |
| W-ORD-054 | 즉시취소의 알림 | 즉시취소 시 공급자에게 시스템 알림 "취소/반품 접수"(즉시취소형 문구)를 발송한다. 구매자 본인이 처리한 건이므로 도매구매 알림은 발송하지 않는다 (→ A-NTF-032 구매자 즉시취소의 알림) |
| W-ORD-055 | 즉시취소의 카드 결제취소 실패 | 카드 결제취소(PayApp)가 실패하면 취소를 처리하지 않고 주문은 기존 상태를 유지한다. 구매자가 다시 시도한다. 결제취소 성공 응답을 확인한 뒤에만 취소승인을 확정한다 (→ OI-W-02) |
| W-ORD-056 | 조정 모드의 처리 | 조정 모드는 요청이 들어온 단계에 한정한다(주문접수 = 취소요청, 배송중 = 반품요청). 승인 / 반려 2지선다 라디오 중 선택하며 기본값은 승인이다. 승인하면 환불 영역과 재고 반영 체크박스를 노출하고 주문 흐름을 종료한다. 반려하면 환불 영역과 재고 반영 체크박스를 숨기고 주문상태를 이전 단계로 복귀한다(취소반려 → 주문접수, 반품반려 → 배송중) |
| W-ORD-057 | 직권 모드의 처리 | 직권 모드는 요청 이력이 없거나 반려로 종료된 건에 한다. 주문접수·배송대기 단계는 취소처리만, 배송중 단계는 반품처리만 할 수 있다. 상태 선택 라디오 없이 제출 즉시 승인 처리하며 팝업 진입 시점부터 환불 영역을 노출한다. 구매자 요청 없이 공급자가 임의로 처리했음을 구분해 기록한다 |
| W-ORD-058 | 종결 건의 추가 처리 불가 | 취소승인·반품승인으로 종결된 건은 이후 어떤 처리도 할 수 없다 |
| W-ORD-059 | 취소·반품 처리 일시의 갱신 | 취소·반품을 처리할 때마다 처리상태와 처리 일시를 갱신하며 최근 1건만 표시한다. 승인으로 종결된 건의 이 일시가 취소·환불액의 기준일(취소·반품 승인 일시)이다 |
| W-ORD-060 | 환불구분·환불금액 규칙 | 카드결제는 전체환불로 고정하며 총환불금액은 총 결제금액(구매자부담 수수료 포함)이고 수정할 수 없다. 계좌이체는 전체환불(기본)과 부분환불 중 선택한다. 전체환불의 총환불금액은 총 결제금액이다. 부분환불의 총환불금액은 상품환불금액(0원 이상, 상품금액 이내) + 배송비 포함 체크 시 배송비다. 환불액은 총환불금액 하나로 저장하며 수수료를 따로 계산하는 환불 산식은 두지 않는다 |
| W-ORD-061 | 부분환불 금액 검증 | 부분환불은 계좌이체에서만 선택할 수 있다. 무료배송·착불 건은 배송비가 0원이므로 "배송비 포함" 체크박스를 노출하지 않는다. 총환불금액이 0원이면 처리 버튼을 비활성화하고 "환불금액을 입력해주세요."를 표시한다 |
| W-ORD-062 | 결제대기 건의 취소·반품 | 결제대기 건은 결제된 금액이 없으므로 금액 조회·환불 입력 블록을 노출하지 않고 "결제 대기 중인 주문으로 환불은 진행되지 않습니다." 안내만 노출한다. 승인해도 환불값을 저장하지 않고 결제상태만 결제취소로 전환한다. 이 경우는 계좌이체에서만 발생한다 |
| W-ORD-063 | 환불 저장값 | 승인 시 환불구분과 총환불금액을 저장한다. 부분환불 건은 상품환불금액과 배송비 환불 포함 여부를 함께 저장한다. 취소·환불액 집계는 총환불금액만 합산한다 |
| W-ORD-064 | 재고 반영의 선택 | 취소·반품이 승인으로 확정되는 시점에만 공급자가 재고 반영 여부를 체크박스로 선택한다(기본값: 선택). 체크하면 주문 전체 품목 수량만큼 공급자 보유수량을 복원한다. 판매가능수량은 변하지 않는다. 복원할 대상(내 도매상품)이 주문 품목 중 하나도 없으면 체크박스를 노출하지 않는다 |
| W-ORD-065 | 보유수량 차감 시점·대상 | 보유수량은 주문이 생성되는 즉시 차감한다. 처리상태 변경 시점이 아니다. 차감 대상은 판매자가 본인인 주문의 품목에 한한다. 판매가능수량은 변하지 않는다 |
| W-ORD-066 | 품목별 부분 처리 미지원 | 취소·반품 처리와 재고 차감·복원은 주문 전체 단위로 일괄 적용한다. 한 주문에 여러 품목이 있어도 품목별 부분 처리는 지원하지 않는다 (→ OI-W-03) |

> **경고** 계좌이체 건의 결제취소는 취소 처리 확정만 뜻한다. 환불 이행은 공급자가 직접 해야 하며 시스템이 환불을 실행하지 않는다 (→ W-ORD-031 계좌이체 건의 결제취소 처리).

> **주의** 카드결제 건의 승인은 PayApp 결제취소 성공 응답을 확인한 뒤에만 확정된다. 실패 시 요청 상태가 유지되므로 재시도 전에 상태를 확인한다 (→ W-ORD-030 카드결제 건의 결제취소 처리).

# 2장. 도·소매 상품 관리 (W-PRD)

## 2.1 적용 범위

- 대상 화면: 도매관리 > 내 도매상품(도매상품등록·수정·상세), 도매상품 주문하기의 검색·필터, 소매관리 > 상품관리(상품목록, 상품카테고리, 소매상품등록, 소매정보등록·수정·상세, 도매상품전환, 메인상품진열)
- 대상 계정: 도매상품을 공급하는 본사·가맹점 계정, 소매몰을 운영하는 본사·가맹점 계정
- 제외 범위: 도매 주문·결제·배송·취소·반품 처리(→ 1장 W-ORD), 소매 주문 접수·취소·반품의 재고 처리(→ 03 파일 R-ORD), 소매설정의 기본 수령방식(→ 03 파일 R-MAL), 채팅주문상품명의 중복확인 규칙(→ 03 파일 R-CHT), 이용제한 계정의 판매 행위 범위(→ 02 파일 A-LGN), 이용불가 전환·도매공급권한 회수 시 상품 일괄 처리의 발동 조건(→ 02 파일 A-FEE)

## 2.2 정의

| 용어 | 정의 |
| --- | --- |
| 내도매상품 | 본인이 직접 등록한 도매상품. 소매로도 판매하는 경우 소매정보를 연결한다 |
| 도매주문상품 | 다른 공급자에게서 구매(배송확정)한 도매상품을 소매로 판매하는 상품 |
| 내소매상품 | 도매 연동 없이 소매몰에서 직접 단독 등록한 상품 |
| 소매정보 | 도매상품·구매한 도매상품·내소매상품을 자기 소매몰에 노출하기 위한 판매정보. 소매정보 ID(내부 식별자, 사용자에게 노출하지 않음)로 구분한다 |
| 연동 상품 | 보유수량이 다른 재고에 종속되는 소매정보. 내도매상품과 도매주문상품이 해당한다 |
| 자체 재고 상품 | 자체 수량을 직접 보유·관리하는 상품. 도매상품과 내소매상품이 해당한다 |
| 소매노출여부의 강제 미노출 | 시스템이 소매노출여부를 미노출로 고정해 사용자가 변경할 수 없는 상태 |
| 도매상품전환 | 내소매상품을 도매상품으로 바꾸는 처리. 되돌릴 수 없다 |
| 메인상품진열 | 소매몰 메인 화면에 노출할 소매상품을 고르고 진열 순서를 정하는 기능 |

상품코드, 상품출처, 소매정보, 보유수량, 판매가능수량, 도매 가용재고, 판매상태, 노출여부는 00 공통 3-5를 따른다.

## 2.3 요건

### 가. 상품코드·소매정보 구조

| ID | 요건명 | 요건 |
| --- | --- | --- |
| W-PRD-001 | 상품코드 체계 | 상품코드는 "P" + 4자리 숫자(예: P0231) 하나의 체계이며 시스템 전체에서 유일하게 채번한다. 도매주문상품, 내도매상품, 내소매상품이 같은 상품코드를 공유한다. 도매·소매 구분은 코드가 아니라 상품출처 필터값으로 한다 |
| W-PRD-002 | 상품출처 표시 | 소매정보 화면(등록·수정·상세·상품목록)은 공급자명을 붙이지 않고 내도매상품 / 도매주문상품 / 내소매상품 구분값만 표시한다. 동일 공급자라도 상품마다 노출 문구가 달라지지 않는다 |
| W-PRD-003 | 소매정보의 소매몰별 독립 | 소매정보는 본사·가맹점(소매몰)마다 독립으로 설정한다. 한 소매몰 안에서 같은 상품코드의 소매정보는 1개다. 소매정보를 등록하지 않으면 소매몰에 노출되지 않는다 |
| W-PRD-004 | 도매주문상품 소매정보의 생성 단위 | 도매주문상품의 소매정보는 주문 단위가 아니라 상품(코드) 단위로 만든다. 한 주문에 여러 상품이 있으면 상품별로 만든다 |
| W-PRD-005 | 재구매 시 수량 누적 | 같은 상품을 다시 구매(배송확정)하면 구매자의 도매주문상품 보유수량(계정 + 상품코드 단위)을 누적한다. 소매정보가 이미 있으면 재구매분의 상품정보로 덮어쓰지 않고 수량만 누적한다 |
| W-PRD-006 | 소매정보 초기값의 기준 | 소매정보가 아직 없으면 소매정보 등록 시 가장 최근 배송확정 구매분의 상품정보를 초기값으로 쓴다 |

### 다. 도매·소매 수량 연동

| ID | 요건명 | 요건 |
| --- | --- | --- |
| W-PRD-011 | 보유수량의 저장 단위 | 보유수량은 계정 + 상품코드 단위로 저장한다. 내도매상품은 공급자가 입력한 수량, 도매주문상품은 배송확정 구매분 누적 수량, 내소매상품은 등록 시 입력한 수량이다. 소매·도매 화면 모두 같은 값을 보유수량으로 표기한다. 소매 등록으로 차감하지 않는다 |
| W-PRD-012 | 판매가능수량의 상한 | 판매가능수량은 소매정보 단위로 저장하며 보유수량 이하여야 한다. 보유수량 중 소매몰에 실제로 노출·판매할 수량을 별도로 지정하는 값이다. 모든 증감 후에도 보유수량 ≥ 판매가능수량을 유지한다. 도매 가용재고는 보유수량 − 판매가능수량으로 산출한다 |
| W-PRD-013 | 보유수량 하향 수정 제한 | 보유수량은 해당 소매정보의 판매가능수량보다 낮게 수정할 수 없다 |
| W-PRD-014 | 소매 판매의 수량 차감 | 소매몰에서 주문이 접수되는 즉시 해당 소매정보의 판매가능수량과 보유수량을 주문 수량만큼 함께 감소한다(상품출처 공통). 소매 취소·반품 승인 시 재고 반영을 선택하면 두 수량을 같은 수량만큼 복원한다 (→ R-ORD-052 판매가능수량·보유수량의 접수 시 차감) |
| W-PRD-015 | 보유수량 차감·복원의 연결 | 공급자 본인 보유수량의 도매 주문 차감 시점·대상과 취소·반품 승인 시 복원은 도매 주문 처리 기준을 따른다. 판매가능수량은 변하지 않는다 (→ W-ORD-064 재고 반영의 선택, W-ORD-065 보유수량 차감 시점·대상) |

| 내 도매상품 검색·필터 | 필터는 공급범위, 도매판매상태, 도매노출여부, 1차 카테고리, 2차 카테고리. 검색 "상품코드, 상품명 검색" |

| 도매상품 주문하기 검색·필터 | 검색 "상품명, 공급자명 검색". 필터는 공급범위(전체 / 전국 / 우리지역 / 우리본사)와 상품카테고리(1차·2차). 정렬은 최신순 / 주문순 / 가격순 |
| 목록 페이지네이션 | 내 도매상품, 도매상품 주문하기, 소매 상품목록 모두 페이지당 20건이며 디자인시스템의 목록 페이지네이션·건수 표시 표준을 따른다 |
| 소매 상품카테고리 화면 | 위치는 소매관리 > 상품관리 > 상품카테고리다. 1차를 선택하면 소속 2차를 표시한다. 1차가 없으면 "1차 카테고리를 먼저 등록해주세요.", 2차가 없으면 "등록된 2차 카테고리가 없습니다."를 안내한다. 카테고리명과 "연동상품 N"(1차는 하위 2차 합계)을 표시한다 |
| 소매 카테고리 추가·수정 | [+ 추가]로 입력 행을 열어 카테고리명을 입력하고 [저장]한다. 2차는 선택된 1차 아래에만 추가할 수 있어 1차가 없으면 [+ 추가]를 비활성화한다. 카테고리명이 비어 있으면 저장하지 않는다. [수정]으로 이름을 바꾸고 [저장] 또는 [취소]한다 |
| 소매 카테고리 삭제 문구 | 연동상품이 있으면 [삭제]는 비활성이며 "연동상품이 있어 삭제할 수 없습니다"를 안내한다. 하위 2차가 있는 1차 삭제 시 "하위 2차 카테고리도 함께 삭제됩니다."를 함께 고지하며 마지막 문장은 "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요."다 |
| 소매 카테고리 순서 | 카테고리를 드래그해 1차끼리, 같은 1차 안의 2차끼리 순서를 바꾼다. 즉시 반영하며 소매정보 등록·수정과 상품목록 필터의 선택 목록 순서에 그대로 쓴다 |
| 카테고리 사용 화면 | 도매 카테고리: 도매상품 등록·수정, 도매상품전환, 내 도매상품 목록·상세, 도매상품 주문하기. 소매 카테고리: 소매정보 등록·수정, 소매상품등록, 소매 상품목록, 소매정보 상세 |
| 메인상품진열 후보 화면 | 후보 목록에 "소매몰에 노출 중인 상품만 표시됩니다." 안내를 둔다. 노출/미노출 구분은 표시하지 않고 품절 여부만 표시한다 |
| 입력 필수 표시 | 필수 입력 항목은 라벨에 `*`를 표기하고 선택 항목은 표기하지 않는다 |
| 우리지역 입력 화면 | 도매상품등록·수정·도매상품전환은 공급범위 옆 칸에 "우리지역" 영역을 두며 공급범위가 우리지역이 아니면 빈 칸으로 둔다. 도매설정은 "공급범위(우리지역) 설정" 섹션에 같은 영역을 둔다. 영역은 필드 제목 → 안내 문구 → [지역 추가]와 "등록 N/50곳" → 지역 칩 순서다. 칩은 기본 지역을 "(기본)"으로 표시하며 삭제 버튼 없이 고정하고, 추가한 지역은 ×로 삭제한다 |
| 우리지역 안내 문구 | "본사 구분 없이, 등록한 우리지역(시·군·구 단위)에 사업장 주소가 있는 모든 가맹점에 노출됩니다. 최대 50곳까지 등록할 수 있습니다." 모든 화면에서 같은 문구를 쓴다 |
| 지역 추가 팝업 | 시·도, 시·군·구를 차례로 선택해 [추가]한다. 오류는 팝업 안에 표시한다. 시·도 미선택 "시·도를 선택해주세요." / 시·군·구 미선택 "시·군·구를 선택해주세요." / 중복(기본 지역 포함) "이미 등록된 지역입니다." / 한도 "최대 50곳까지 등록할 수 있습니다." |
| 우리지역 상세 표기 | 도매상품 상세의 공급범위에 "우리지역 (기본 지역 외 N곳)"을 표기하고, 추가한 지역이 있으면 다음 줄에 " / "로 구분해 나열한다. 괄호 안에는 기본 지역을 표기한다 |
| 이미지 안내 | "2장 이상 등록 · 첫번째 이미지가 대표이미지로 노출됩니다" 안내를 둔다. 이미지는 개별 삭제할 수 있다 |
| 이미지 오류 문구 | 2장 미만: "상품이미지를 2장 이상 등록해주세요." / 11장째: "이미지는 최대 10장까지 등록할 수 있습니다." / 형식: "JPG, PNG, WEBP 이미지 파일만 등록할 수 있습니다." / 용량: "이미지는 파일당 5MB 이하만 등록할 수 있습니다." |
| 필드 오류 문구 | 상품명 "상품명을 입력해주세요." / 카테고리 "카테고리 1차를 선택해주세요."(소매정보 입력 영역: "소매정보의 카테고리 1차를 선택해주세요.") / 공급가 "공급가를 입력해주세요."·"공급가는 1원 이상의 정수로 입력해주세요." / 소비자가 "소비자가를 입력해주세요."·"소비자가는 1원 이상의 정수로 입력해주세요." / 할인가 "할인가는 1원 이상의 정수로 입력해주세요."·"할인가는 소비자가를 초과할 수 없습니다." / 보유수량 "보유수량을 입력해주세요."·"보유수량은 0 이상의 정수로 입력해주세요." / 판매가능수량 "판매가능수량을 입력해주세요."·"판매가능수량은 0 이상의 정수로 입력해주세요."·"판매가능수량은 보유수량을 초과할 수 없습니다." / 픽업가능기간 "픽업가능 시작일·종료일을 입력해주세요."·"픽업가능 종료일은 시작일보다 빠를 수 없습니다."·"픽업가능 종료일은 오늘 이후로 입력해주세요." |
| 입력 검증의 화면별 적용 범위 | 상품이미지·상품명·카테고리 1차: 4개 화면 모두. 공급가: 도매상품등록, 도매상품전환. 소비자가·할인가: 도매상품등록("소매정보 함께 등록" 선택 시), 소매정보등록·수정, 소매상품등록(도매상품전환은 기존 소매정보 유지). 보유수량: 도매상품등록, 소매상품등록, 도매상품전환, 소매정보 수정(내소매상품만). 판매가능수량: 도매상품등록("소매정보 함께 등록" 선택 시), 소매정보등록·수정(도매연동 상품만), 도매상품전환. 픽업가능기간: 수령방식에 픽업이 포함될 때 도매상품등록("소매정보 함께 등록" 선택 시), 소매정보등록·수정, 소매상품등록. 채팅주문상품명: 채팅주문허용 시 도매상품등록("소매정보 함께 등록" 선택 시), 소매정보등록·수정, 소매상품등록. 등록 지역: 공급범위가 우리지역일 때 도매상품등록·수정, 도매상품전환(필수 검증 없음, 오류는 [지역 추가] 팝업 안에 표시) |

## 2.4 절차·상태 전이

소매정보 등록 흐름

| 단계 | 처리 |
| --- | --- |
| 1 | 도매상품등록 시 "소매정보 함께 등록"을 체크하거나, 상품목록에서 [소매정보등록]을 누르거나, 소매상품등록에서 신규 등록한다 (→ W-PRD-003) |
| 2 | 입력값을 검증한다. 오류가 있으면 저장하지 않고 오류 문구를 모두 나열한다 (→ W-PRD-046) |
| 3 | 입력한 수량으로 판매상태를 산정한다. 0이면 품절, 0 초과면 판매중이다 (→ W-PRD-016) |
| 4 | 소매몰 노출 중이면 메인상품진열 후보가 된다 (→ W-PRD-043) |

소매 판매상태·노출여부 잠금 판정

| 번호 | 조건 | 결과 |
| --- | --- | --- |
| 1 | 보유수량 0 | 판매상태 강제 품절, 노출여부 강제 미노출 (→ W-PRD-017, W-PRD-018) |
| 2 | 픽업 포함 수령방식이고 픽업가능종료일 경과 | 노출여부 강제 미노출. 판매상태는 수량 기준 (→ W-PRD-019) |
| 3 | 보유수량 > 0, 판매가능수량 0 | 판매상태만 자동 품절. 노출여부에는 영향 없음 (→ W-PRD-020) |
| 4 | 위 조건에 모두 해당하지 않음 | 판매상태·노출여부 자유 전환 |

조건은 각각 독립적으로 판정하며, 둘 이상 해당하면 각 조건이 자기 필드만 잠근다.

도매상품전환 흐름

| 단계 | 처리 |
| --- | --- |
| 1 | 내소매상품 건의 [도매상품전환]을 눌러 전환 화면으로 이동한다 (→ W-PRD-007) |
| 2 | 상단 배너로 비가역성을 확인하고 도매정보를 입력한다 (→ W-PRD-008, W-PRD-010) |
| 3 | [전환하기]를 눌러 검증을 통과하면 상품출처가 내도매상품으로 바뀌고 내 도매상품 목록으로 이동한다 (→ W-PRD-009) |

## 2.5 예외·실패

| 상황 | 처리 |
| --- | --- |
| 연동 상품의 보유수량 0 | 화면은 조회 전용이며 [삭제]만 가능하다 (→ W-PRD-017) |
| 내소매상품의 보유수량 0 | 판매상태·노출여부만 잠그고 보유수량 재입력으로 해제한다 (→ W-PRD-018) |
| 보유수량을 판매가능수량보다 낮게 수정 | 수정할 수 없다 (→ W-PRD-013) |
| 판매가능수량이 보유수량 초과 | "판매가능수량은 보유수량을 초과할 수 없습니다."로 저장을 막는다 (→ W-PRD-049) |
| 이용제한 계정의 도매상품전환 | 버튼을 비활성화하고 전환 화면 진입을 차단한다 (→ W-PRD-007) |
| 진행 중 주문이 있는 상품 삭제 | 차단하지 않고 확인 창으로 고지한 뒤 삭제한다. 기존 주문은 스냅샷으로 유지한다 (→ W-PRD-029, W-PRD-031) |
| 연동상품이 있는 소매 카테고리 삭제 | [삭제]를 비활성화한다 (→ W-PRD-042) |
| 미노출로 전환된 상품이 진열 중 | 메인상품진열에서 자동 삭제한다. 다시 노출해도 복귀하지 않는다 (→ W-PRD-044) |
| 이용불가 전환 후 해제·이용승인 | 일괄 품절·미노출 처리된 상품은 자동 복구하지 않는다. 가맹점이 상품별로 직접 판매중·노출로 바꾼다 (→ W-PRD-053) |
| 등록 지역이 한도(50곳)에 도달 | [지역 추가]를 비활성화한다 (→ W-PRD-056) |
| 이미 등록된 지역 추가 | "이미 등록된 지역입니다."로 추가를 막는다. 기본 지역도 같다 (→ W-PRD-056) |
| 소매 카테고리가 없는 상태에서 소매정보 등록 | 1차 카테고리를 선택할 수 없으므로 소매 상품카테고리를 먼저 등록해야 한다 (→ W-PRD-041) |
| 저장하지 않고 메인상품진열 화면 이탈 | 변경을 반영하지 않는다 (→ W-PRD-045) |

## 2.7 미결 사항

이 장 고유의 미결 사항은 없다. 1.7절의 OI-W-03(품목별 부분 취소·반품과 품목별 재고 반영 여부 선택)이 이 장의 재고 반영 규칙에도 적용되며, OI-W-06(시·군·구 판정 방식)과 OI-W-07(사업장 주소 변경과 기본 지역)이 등록 지역 규칙에 적용된다.
