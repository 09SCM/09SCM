# 09SCM관리자 — 시스템관리 알림설정 정책정리안

기준일: 2026-10-06
범위: 시스템관리 > 알림설정(소매몰 알림톡 설정 탭 / 시스템 알림 설정 탭), 알림센터
관련 문서: `09SCM관리자_소매몰설정_정책정리안`, `09SCM관리자_소매주문처리_정책정리안`, `09SCM관리자_도매주문처리_정책정리안`(도매 알림 트리거 근거), `09SCM관리자_도소매상품관리_정책정리안`, `09SCM관리자_채팅주문_정책정리안`(채팅주문 매칭실패·상품별 개별 주문 생성 근거), `09SCM소매몰_주문내역취소반품_정책정리안`(소매 취소·반품 요청접수 근거)

## 1. 결론 요약

- 시스템관리 > 알림설정은 2개 탭으로 구성한다: **소매몰 알림톡 설정**(고객에게 보내는 유료 알림톡, 템플릿 8종) / **시스템 알림 설정**(관리자 본인이 받는 무료 알림).
- 시스템 알림 설정은 **도매구매 / 도매판매 / 소매 / 시스템** 4개 카테고리, 총 **16개 케이스**로 구성하며, **전체 알림 받기(마스터 토글) > 카테고리 토글 > 케이스별 개별 토글**의 3단 구조로 관리한다. **도매상품 알림**(우리본사상품등록)도 전체 알림 받기 하위 항목이다 — 4개 카테고리처럼 묶지는 않지만(케이스 1개뿐) 마스터 토글의 영향은 동일하게 받는다.
- 4개 카테고리는 "누가 이 알림을 받는가"(수신 성격) 기준으로 묶은 그룹이다. 발송 트리거가 사용자의 버튼 클릭인지 시스템의 자동 감지인지는 카테고리를 나누는 기준이 아니므로, 같은 카테고리 안에서도 케이스마다 트리거 방식이 다를 수 있다(예: 소매 카테고리는 신규주문접수처럼 사용자 액션 기반 케이스와 노쇼후보 발생처럼 시스템 자동 감지 기반 케이스가 함께 있다).
- 상위 토글을 끄면 하위 항목은 **화면에서 완전히 숨김 처리**된다(비활성화 표시가 아니라 비노출). 전체 알림 받기를 끄면 4개 카테고리 섹션과 도매상품 알림 섹션이 모두 사라지고, 카테고리 토글을 끄면 그 카테고리의 케이스 목록만 사라진다(카테고리 토글 자체는 계속 노출되어 다시 켤 수 있다). 각 항목의 on/off 값 자체는 숨겨진 동안에도 보존되어, 다시 켜면 이전 설정 그대로 복원된다.
- 이 16개 케이스와 도매상품 알림은 **알림센터와 웹푸시에 동일하게 반영**되며, 채널별로 발송 대상을 구분하지 않는다.
- **알림을 끄면(마스터/카테고리/케이스 중 무엇을 껐든) 꺼져 있는 동안 발생한 알림은 웹푸시뿐 아니라 알림센터에도 쌓이지 않는다.** 다시 켜도 꺼져 있던 기간의 알림은 표시되지 않는다. 끄기 이전에 이미 쌓인 알림은 이력으로 알림센터에 그대로 남아 계속 표시된다.
- 알림센터는 **확인(클릭) = 삭제** 방식이다. 개별 클릭 또는 "모두 확인"으로 목록에서 삭제해도, 각 알림이 참조한 원 데이터(주문내역, 발송내역 등)는 해당 도메인 화면에 그대로 남아 있으므로 정보 유실이 아니다.
- 알림센터의 시간은 1분 미만 "방금", 60분 미만 "N분 전", 24시간 미만 "N시간 전", 그 이후 `YY.MM.DD HH:MM`으로 표시한다(6절).
- 웹푸시 제목은 `[카테고리] 케이스명` 형식을 고정 사용한다(예: `[도매구매] 결제확인 처리`, `[소매] 신규주문접수(결제완료)`).
- 배송확정은 구매자·판매자 어느 쪽이든 처리할 수 있으므로(도매주문처리 정책의 대리처리 허용), 배송확정 알림은 **처리한 사람이 아니라 상대방에게** 발송된다 — 도매구매·도매판매 두 카테고리에 각각 별도 케이스로 존재한다.
- 소매 신규주문접수는 주문 생성 시 결제상태 기준으로 **결제완료 / 결제대기** 2개 케이스로 나뉜다. 카드결제는 결제완료, 계좌이체·현장결제는 결제대기로 생성되므로 각각 해당 케이스로 발송한다.
- 신규주문접수(결제완료)·신규주문접수(결제대기)는 도매판매·소매 카테고리 모두 기본값을 미사용(off)으로 두고, 알림이 많이 발송될 수 있어 끄는 것을 권장한다는 안내 문구를 표시한다. 주문 1건마다 알림 1건이 발송되며, 특히 채팅주문은 상품마다 개별 주문으로 생성되기 때문이다. 두 카테고리에 같은 기준을 적용한다.
- 소매몰 알림톡 1번 템플릿(주문접수완료(카드결제/현장결제))은 채팅주문에는 발송하지 않는다. 채팅주문은 채팅방 접수 안내로 대신하며, 이후 단계(결제확인완료·픽업대기·픽업/배달완료·취소/반품승인) 알림톡은 채팅주문에도 발송한다.
- 알림톡 잔여건수가 5건 미만이 되면 알림톡 발송을 중단하고 알림톡 사용하기를 자동으로 끄며, 시스템 알림 "알림톡 잔여건수 부족"을 1회 발송한다. 주문 처리에는 영향이 없고, 충전 후에도 알림톡 사용하기는 직접 켜야 한다(4-2절).
- 소비자 발송 문구(알림톡·채팅방 접수 안내)와 관리자 화면의 일시·날짜 표기 형식은 디자인시스템 문서의 "날짜·일시 표기"를 따른다. 알림톡 픽업기간 변수(`#공통픽업가능기간`)는 주문에 저장된 공통 픽업가능기간을 사용한다.

## 3. 발송 트리거 공통 원칙

- 알림은 원칙적으로 사용자가 화면에서 명시적으로 누른 버튼(주문하기, 결제확인, 처리상태 다음단계 처리(일괄변경 포함), 배송확정, 취소·반품 승인/반려 제출 등)에 대해 발송한다.
- 알림 채널에 따라 수신 대상이 다르다. 소매몰 알림톡(외부 고객, 유료)은 상태 이벤트마다 액션 주체와 무관하게 고객에게 발송한다(예: 고객 본인이 주문·즉시취소한 건에도 접수완료·취소/반품승인 알림톡 발송). 시스템 알림(관리자, 무료 웹푸시·알림센터)은 처리한 당사자가 아니라 상대방에게 발송한다(5-6절).
- 되돌리기(직전 단계 복귀)로 처리상태가 다시 바뀌면 해당 단계 알림을 정상 발송한다(소매 알림톡 4~6번, 도매구매 2·3번). 주문접수로 되돌릴 때는 대응하는 템플릿·케이스가 없어 발송하지 않는다.
- 시스템이 부수적으로 자동 파생시키는 상태 변화에는 별도 알림을 발송하지 않는다. 예: 배송확정 처리 시점에 결제상태가 결제대기였다면 결제완료로 자동 전환되는데(도매주문처리 정책), 이 결제상태 자동전환 자체에는 "결제상태변경" 알림을 발송하지 않는다. 소매몰 알림톡은 발송 1건마다 과금되므로, 사용자의 액션 1회에 대해 파생 알림까지 중복 발송되면 불필요한 과금 손해로 이어지기 때문이다.
- 다만 이 원칙은 "케이스 단위 발송 기준"이며, "카테고리를 나누는 기준"과는 별개다. 5절의 4개 카테고리는 수신 성격(누가 받는가)으로 묶은 그룹이므로, 카테고리 안에 시스템이 상태·수치를 감지해 자동 발생시키는 케이스가 포함될 수 있다 — 소매 카테고리의 "노쇼후보 발생"·"채팅주문 매칭실패", 시스템 카테고리의 "가맹점 이용료 결제실패"·"알림톡 잔여건수 부족" 4건이 이에 해당한다. 이 4건은 예외적 오류가 아니라 해당 그룹의 정상적인 발송 방식이다.

## 4. 소매몰 알림톡 설정 (고객발송, 유료)

### 4-1. 채널·과금 구조

| 항목 | 내용 |
| --- | --- |
| 발송 채널 | 09SCM 공용 알림톡 채널(템플릿 기반) |
| 과금 방식 | 유료 부가서비스, 건별 차감(충전형) |
| 잔여 건수 부족 시 동작 | 잔여 건수가 5건 미만이 되면 알림톡 발송 중단, 알림톡 사용하기 자동 off, 시스템 알림 1회 발송(5-5절). 주문 처리에는 영향이 없다. 알림톡 사용하기를 다시 켜려면 잔여 건수 5건 이상이 필요하다(4-2절) |
| 대체 발송 | 알림톡 발송 실패 시 LMS로 자동 대체 발송된다 |
| 건당 차감 | 알림톡 1건 = 1건 차감 / LMS 1건 = 4건 차감 |

### 4-2. 화면 구성

- 통계: 잔여알림톡 건수([충전하기] 버튼 제공), 이번달 발송 건수(알림톡·LMS 건수 병기)
- 알림톡 안내 문구: "사용 설정한 발송메시지는 지정된 양식에 따라 09SCM 알림톡 채널을 통해 자동 발송됩니다. 알림톡은 유료 부가서비스로 충전 후 사용할 수 있으며, 잔여 건수가 5건 미만이 되면 알림톡 사용하기가 자동으로 꺼집니다. 발송 실패 시 LMS로 대체 발송됩니다." 안내 문구 고정 노출
- 알림톡 사용하기(마스터 토글): 끄면 아래 발송 메시지 섹션 자체가 화면에서 사라진다(각 템플릿의 개별 on/off 값은 보존되며, 다시 켜면 이전 설정값 그대로 복원된다)
  - 잔여건수가 5건 미만이 되면 알림톡 발송을 중단하고 알림톡 사용하기를 자동으로 끄며, 시스템 알림 "알림톡 잔여건수 부족"을 1회 발송한다(5-5절 시스템 2번). 주문 처리에는 영향이 없다.
  - 알림톡 사용하기를 켜려면 잔여건수가 5건 이상이어야 한다. 5건 미만에서 켜기를 시도하면 "잔여 알림톡이 5건 미만이라 사용할 수 없습니다. 충전 후 설정해 주세요." 안내를 노출하고 켜지지 않는다.
  - 충전해도 알림톡 사용하기는 자동으로 켜지지 않으며 직접 켜야 한다.
  - 신규 가맹점 계정의 초기 상태는 잔여건수 0건, 알림톡 사용하기 꺼짐이다. 켜려면 먼저 충전해 잔여건수를 5건 이상으로 만들어야 한다.
- 발송 메시지(마스터 on일 때만 노출): 템플릿 8종. 각 항목에 제목+본문 미리보기와 템플릿별 개별 on/off를 둔다
- 발송내역: 기간 필터(전체/1개월/3개월/6개월/기간 직접입력), [발송 메시지][발송채널] 필터, 수신자 검색, 발송 목록(4-5절), 페이지네이션

### 5-6. 배송확정 양방향 알림 처리

배송확정은 구매자·판매자 어느 쪽이든 처리할 수 있다(도매주문처리 정책의 대리처리 허용). 이에 따라 배송확정 알림은 "처리한 사람이 아니라 상대방"에게 발송되도록 도매구매·도매판매 카테고리에 각각 별도 케이스를 둔다 — 판매자가 배송확정을 처리하면 구매자에게(도매구매 4번), 구매자가 배송확정을 처리하면 판매자에게(도매판매 3번) 발송된다. 배송중 전환(반품반려 복귀 건은 반려 일시) 후 7일 경과로 시스템이 자동 배송확정한 건은 처리 주체가 없으므로 구매자(도매구매 4번)·판매자(도매판매 3번) 모두에게 발송한다. 자동 배송확정은 별도 알림 케이스나 토글을 두지 않고 각 배송확정 처리 케이스의 하위 변형으로 관리하며, 본문은 "주문(#주문번호)이 배송확정 처리되었습니다."를 사용한다. 발송 여부는 구매자·판매자 각각 해당 케이스의 사용 토글을 따른다. 반품반려로 배송중에 복귀한 건에 대해서는 복귀 시점의 별도 알림을 두지 않는다(반려 결과는 취소/반품 결과안내로 이미 발송된다).

| 설정 연동 | **꺼져 있는 동안 발생한 알림은 알림센터에 쌓이지 않는다.** 마스터 토글, 카테고리 토글, 케이스별 토글, 도매상품 알림 토글 중 어느 하나라도 꺼져 있으면 그 기간에 발생한 알림은 웹푸시뿐 아니라 알림센터에도 쌓이지 않으며, 다시 켜도 표시되지 않는다. 끄기 이전에 쌓인 알림은 설정과 무관하게 이력으로 계속 표시된다 |
| 정렬 | 발생 일시 기준 최신순. 발생 일시가 같으면 나중에 생성된 알림이 위에 온다 |
| 뱃지 | 알림센터에 알림이 1건 이상 있으면 벨 아이콘에 표시점(dot) 노출, 0건이면 숨김 |
| 항목 표시 | `[카테고리]` 태그, 발생 시간, 본문(케이스 문구의 변수를 실제 값으로 치환) |
| 시간 표기 | 발생 시각 기준 1분 미만은 "방금", 60분 미만은 "N분 전", 24시간 미만은 "N시간 전", 24시간 이상은 일시 형식(디자인시스템 "날짜·일시 표기")으로 표시한다. 알림은 발생 일시를 함께 보관한다 |
| 확인 = 삭제 | 항목을 클릭하면 즉시 목록에서 삭제된다. "모두 확인" 버튼으로 전체를 한 번에 삭제할 수 있다 |
| 삭제 시 데이터 보존 | 알림센터 목록에서만 삭제되며, 각 알림이 참조한 원 데이터(주문내역, 발송내역 등)는 해당 도메인 화면에 그대로 남는다. 전체/미확인 필터를 별도로 두지 않은 이유이기도 하다 |
| 빈 상태 | 알림이 없으면 "새로운 알림이 없습니다." 안내 노출 |
