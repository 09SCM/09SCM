# 09SCM관리자 — 도매주문처리 정책정리안

기준일: 2026-10-20
범위: 09SCM 본사/가맹점 관리자의 도매관리 메뉴 — 도매상품 주문하기(구매) → 장바구니/주문서 작성 → 주문내역(구매자) / 주문접수관리(공급자) → 취소·반품 처리 → 도매매출조회

## 1. 결론 요약

- 도매주문은 노출 → 장바구니/바로구매 → 주문서 작성 → 결제 → 주문접수 → 배송처리 → 배송확정 순으로 진행하며, 취소·반품은 별도 분기로 처리한다.
- 장바구니는 여러 공급자의 상품을 동시에 담을 수 있지만, 결제(주문서 작성) 단위는 항상 공급자 1개로 고정된다.
- 장바구니 품목이 공급범위 변경 등으로 구매자에게 더 이상 노출되지 않으면 [구매불가]로 표시하고 주문 버튼 활성 조건에서 제외한다. 미노출·삭제된 상품은 안내 없이 장바구니에서 제거한다(4절).
- 공급자는 본인이 등록한 도매상품을 본인 계정으로 구매할 수 없다. 결제처리 혼란과 결제수단 악용 가능성을 막기 위한 조치다.
- 도매상품은 공급범위(전국/우리지역/우리본사)에 따라 구매자에게 노출된다. 우리지역은 상품별로 등록한 시·군·구 목록(등록 지역)에 구매자 사업장 주소의 시·군·구가 포함될 때 노출하며, 본사 소속 여부는 판정하지 않는다(2-1절).
- 도매 구매자는 구매 계정의 아이디로 연결하며(가입 후 변경 불가), 도매 주문 품목은 시스템 전체가 공유하는 도매상품 코드("P" + 4자리 숫자)로 표시한다(2-2절).
- 배송비는 상품 단위가 아니라 공급자 단위로 설정한 값(무료배송 / 기본배송비 / 착불) 하나가 그 공급자의 모든 상품에 예외 없이 적용되며, 주문 생성 시점의 배송방식과 배송비를 주문에 스냅샷으로 저장한다.
- 결제상태는 결제대기/결제완료/결제취소이며, 취소·반품승인 확정 시 결제취소로 전환된다(6-1-1).
- 결제확인(결제대기→결제완료)과 처리상태 변경(주문접수/배송대기/배송중)은 서로 완전히 독립된 조작이다. 처리상태는 목록·상세의 다음단계 버튼으로 한 단계씩 진행하고 [되돌리기]로 직전 단계로 복귀하며, 여러 건은 목록의 일괄변경으로 처리한다. 결제완료로 전환되는 시점의 일시를 결제완료 일시로 기록하며, 이 값이 매출조회 결제총액의 기준일이다.
- 구매자의 반품요청은 배송중 전환 후 7일 이내로 제한된다. 배송중으로 전환된 지 7일이 지나면 자동으로 배송확정되며, 이후에는 반품요청이 불가능하다.
- 구매자는 주문접수 단계에서 카드결제 건과 결제대기 건을 승인 없이 즉시 취소할 수 있고(구매자 즉시취소), 계좌이체 결제완료 건은 취소요청(공급자 승인)으로 진행한다.
- 배송대기 단계에서는 구매자가 취소·반품을 요청할 수 없다. 이는 무분별한 취소요청을 막기 위한 의도된 제약이며, 공급자는 구매자 요청 여부와 무관하게 어느 단계에서든 취소·반품을 직권으로 처리할 수 있다.
- 취소·반품 처리 팝업의 처리 방식은 승인/반려 2지선다로 통일한다. 환불액은 "총환불금액" 하나로 저장하며, 카드결제는 총 결제금액 전액(구매자부담 카드수수료 포함)을 환불하고, 계좌이체는 전체환불 또는 부분환불(상품환불금액 + 배송비 포함 여부)을 선택한다. 결제대기 건은 환불이 진행되지 않는다.
- 도매매출조회는 결제총액 / 취소·환불액 / 매출액 3개 항목으로 구성하며, 매출액 = 결제총액 − 취소·환불액이다. 소매매출조회와 동일한 산식·기준일을 사용하고, 조회 결과를 엑셀로 내려받을 수 있다.
- 결제내역 메뉴는 두지 않는다. 결제확인·배송확정·취소·반품 처리 등 결제와 관련된 모든 처리가 주문접수관리·주문내역에서 이루어지므로 별도 결제내역 화면은 의미가 없다.

## 2. 주문 처리 흐름

1. 공급자가 도매상품을 등록하고 도매노출여부를 켜면 공급범위에 해당하는 구매자의 도매상품 주문하기(구매자용 카탈로그)에 노출된다(2-1절).
2. 구매자는 도매상품 주문하기에서 장바구니에 담거나(여러 공급자 혼재 가능) 상품상세에서 바로구매한다. 본인이 등록한 상품은 구매 버튼 자체가 노출되지 않는다.
3. 장바구니는 공급자별로 그룹 표시되며, 그룹(공급자) 단위로 주문서를 작성한다.
4. 주문서 작성에서 배송지·결제수단을 선택해 결제한다. 카드결제는 즉시 결제완료, 계좌이체는 결제대기 상태로 주문이 생성된다.
5. 주문 생성 시점에 해당 상품 판매자(공급자) 본인의 보유수량이 즉시 차감된다.
6. 공급자는 처리상태(주문접수/배송대기/배송중)를 다음단계 버튼으로 한 단계씩 진행하고, 직전 단계로 돌아가야 하면 [되돌리기]를 사용한다. 결제확인([결제확인] 버튼으로 결제대기 건을 결제완료로 전환)은 처리상태 변경과 무관한 별도 조작이며, 계좌이체·카드결제 어느 쪽이든 동일한 결제확인 조작을 사용한다.
7. 배송대기 단계에서는 구매자의 취소·반품 요청 화면이 없으며, 공급자는 이 단계에서도 취소처리(직권)를 할 수 있다.
8. 배송중 단계에서는 구매자가 반품요청을 하거나 배송확정을 할 수 있고, 공급자도 반품처리(직권) 또는 배송확정 처리를 할 수 있다. 배송확정은 별도 확인 팝업을 거쳐 처리되며, 이 시점에 결제상태가 아직 결제대기라면 결제상태도 함께 결제완료로 자동 전환된다.
9. 배송확정되면 더 이상 상태 변경·취소·반품이 불가능하며, 해당 도매상품(상품코드 단위)은 구매자의 소매정보등록 대상이 된다.
10. 주문접수 단계에서는 구매자가 취소할 수 있고(카드결제·결제대기 건은 즉시취소, 계좌이체 결제완료 건은 취소요청), 공급자는 취소처리(직권 또는 요청 조정)를 할 수 있다.

### 2-1. 공급범위별 구매자 노출

도매상품은 공급자가 지정한 공급범위에 따라 구매자의 도매상품 주문하기 목록에 노출된다.

| 공급범위 | 노출 대상 구매자 |
| --- | --- |
| 전국 | 모든 구매자 |
| 우리지역 | 구매자 사업장 주소의 시·군·구가 상품의 등록 지역에 포함된 구매자. 본사 소속 여부와 무관하다 |
| 우리본사 | 같은 본사 소속 가맹점 |

우리지역 노출 판정은 아래 기준을 따른다. 등록 지역의 등록·수정 규칙은 `09SCM관리자_도소매상품관리_정책정리안` 8-2절을 따른다.

- 판정 기준은 구매자 사업장 주소의 시·군·구다. 상품의 등록 지역(기본 지역 + 추가한 지역)에 구매자의 시·군·구가 포함되면 노출한다. 시 아래에 일반구가 있는 지역은 시와 구를 한 단위로 본다(예: 경기 수원시 영통구).
- 기본 지역은 공급자 사업장 주소의 시·군·구이며 삭제할 수 없다. 공급자의 사업장 주소가 바뀌면 기본 지역도 바뀐 주소 기준으로 적용한다.
- 본사 소속 여부는 판정에 쓰지 않는다. 소속 본사가 달라도 사업장 주소가 등록된 시·군·구에 있으면 노출한다.
- 공급자 본인의 상품은 공급범위와 관계없이 본인의 도매상품 주문하기 목록에 노출한다(구매 제한은 3절).
- 공급범위·등록 지역을 변경해도 이미 생성된 주문과 진행 중인 주문은 영향을 받지 않는다.
- 구매자 화면의 공급범위 필터와 상품 표기는 "우리지역"으로만 표시하며 시·군·구 목록은 노출하지 않는다.

구매자 화면(도매상품 주문하기)에서 공급범위 안내 도움말을 열람할 수 있다. 공급범위가 공급자가 도매상품을 노출할 구매자의 범위임을 안내하고 세 범위의 의미를 설명하며, 문구는 아래와 같다.

- "공급범위란 공급자가 도매상품을 노출할 구매자의 범위입니다."
- "전국: 모든 구매자에게 노출됩니다."
- "우리지역: 공급자가 공급 가능한 우리지역으로 등록한 시·군·구의 구매자에게 노출됩니다."
- "우리본사: 공급자와 같은 본사 소속 가맹점에게만 노출됩니다."

도매공급권한 회수 또는 공급자 이용불가 전환 시 공급자의 도매상품 일괄 품절·미노출과 진행중 주문 처리 원칙은 `09SCM관리자_가맹점이용상태이용료정기결제_정책정리안`을 따른다. 일괄 품절·미노출 처리된 도매상품은 도매상품의 품절·미노출 규칙을 따른다(아래 "장바구니 품절·구매불가 처리와 주문 시점 재검증").

### 2-2. 구매 주체와 주문 품목 식별

- 도매 구매자는 구매 계정의 아이디로 연결한다. 아이디는 가입 후 변경할 수 없다.
- 도매 주문 품목은 도매상품 코드로 표시한다. 상품코드는 도매·소매 구분 없이 "P" + 4자리 숫자(예: P0231)의 단일 체계이며, 모든 공급자·구매자가 같은 코드를 공유한다(`09SCM관리자_도소매상품관리_정책정리안` 2-2절).

## 3. 구매 제한 — 공급자 본인 상품

| 항목 | 내용 |
| --- | --- |
| 정책 | 상품의 판매자가 로그인 계정 본인이면 그 상품은 구매(장바구니 담기·바로구매)할 수 없다. 화면에서 구매 버튼을 노출하지 않는 것에 더해, 주문 생성 처리 단계에서도 동일 조건을 재검증해 화면 요소를 우회한 주문 생성도 차단한다. |
| 사유 | 본인이 본인 상품을 구매하면 결제처리 흐름이 혼란스러워질 뿐 아니라, 카드 돌려막기 등 결제수단 악용 경로로 이용될 가능성이 있다. |
| 화면 표시 | 목록·상세 화면에 "내 상품" 배지를 노출하고, 상세 화면에는 구매 버튼 대신 구매 불가 안내만 표시한다. |
| 서버 검증 | 구매 제한은 화면 노출뿐 아니라 주문 생성 시점의 서버 검증에서도 동일하게 적용한다. 서버 검증 방식은 개발 확인 필요. |

## 4. 장바구니·주문 생성 단위

| 항목 | 내용 |
| --- | --- |
| 장바구니 구성 | 여러 공급자의 상품을 동시에 담을 수 있다. |
| 주문서 작성 단위 | 장바구니는 담긴 상품을 공급자별로 그룹핑해 보여주며, 그룹마다 금액 요약과 [선택상품주문]·[전체주문]을 별도로 제공한다(화면 구성은 아래 "장바구니 화면 구성"). 하나의 주문서(주문번호)는 항상 단일 공급자 품목으로만 구성된다. |
| 바로구매 | 상품상세에서 바로구매를 선택하면 장바구니를 거치지 않고 해당 공급자 1건짜리 주문서로 즉시 이동한다. 본인 상품은 바로구매 버튼 자체가 노출되지 않는다. |
| 수량 변경 시점 | 주문서 작성 화면에서는 품목 수량을 변경할 수 없다. 수량 변경은 장바구니 화면에서만 가능하다. |

장바구니 자체는 여러 공급자를 담을 수 있으나, 결제·주문 단위는 항상 공급자별로 쪼개진다.

### 도매 가용재고와 구매 수량 상한

- 구매자가 한 번에 주문할 수 있는 수량의 상한은 도매 가용재고(= 보유수량 − 소매 판매가능수량)다. 소매에 배정된 판매가능수량은 도매 구매자가 주문할 수 없다.
- 도매상품 주문하기 상품상세 하단 바의 주문수량 옆에 "주문가능수량 N개"로 표기한다(N은 도매 가용재고). 상품상세·장바구니의 수량 증가는 도매 가용재고를 넘을 수 없다.
- 도매 가용재고가 0이면 해당 상품은 품절로 표시한다(도매판매상태 품절 포함).

### 장바구니 화면 구성

- 장바구니 건수 N은 장바구니에 담긴 품목(상품코드)의 수이며 주문 수량의 합계가 아니다. 같은 상품을 다시 담으면 품목은 늘지 않고 기존 품목의 수량만 늘어난다. 도매상품 주문하기 상단의 [장바구니 (N)] 버튼과 아래의 `전체 N건`은 같은 기준을 쓰며, 장바구니가 비어 있으면 버튼에 건수를 표기하지 않는다. 미노출·삭제로 제거되는 품목은 건수에 포함하지 않는다.
- 상단 툴바는 전체 선택 체크박스, `전체 N건 | 선택 N건`, [일괄삭제]로 구성한다. 전체 선택 체크박스는 장바구니 전체 품목을 선택·해제하고, [일괄삭제]는 선택한 품목을 삭제하며 선택이 없으면 비활성이다.
- 공급자 그룹 헤더는 그룹 체크박스, 공급자명, 해당 그룹 기준 `전체 N건 | 선택 N건`으로 구성한다. 그룹 체크박스는 그룹 품목 전체를 선택·해제한다. 배송방식 뱃지는 두지 않는다.
- 그룹 하단 금액 요약은 선택상품금액 / 전체상품금액 / 배송비 / 총 주문금액 4개 항목을 이 순서의 독립 항목으로 표기한다. 배송비는 공급자 도매설정 기준 `무료배송(0원)` / `착불(별도부과)` / `기본배송비(N원)`로 표기하고, 총 주문금액은 선택상품금액에 배송비(무료배송·착불은 0원)를 더한 값이다. 선택한 품목이 없으면 선택상품금액과 총 주문금액은 0원이고 배송비를 가산하지 않는다.
- 주문 버튼은 [선택상품주문]과 [전체주문]이다. [선택상품주문]은 해당 그룹에서 선택한 품목만 주문서로 전달하며 선택이 없으면 비활성이다. [전체주문]은 해당 그룹의 품목 전체를 전달한다. 주문이 완료된 품목만 장바구니에서 제거한다.
- 공급자 그룹 사이에는 구분선을 둔다. 장바구니 전체 합계는 표기하지 않는다(주문은 공급자 그룹 단위로만 생성된다).

### 장바구니 품절·구매불가 처리와 주문 시점 재검증

- 장바구니에 담은 상품의 도매판매상태가 품절이거나 도매 가용재고가 0이 되면 해당 품목에 [품절] 뱃지를 표시한다.
- 장바구니에 담은 상품이 공급범위·등록 지역 변경 또는 구매자 사업장 주소 변경으로 구매자에게 더 이상 노출되지 않으면(도매노출여부는 노출 상태) 해당 품목에 [구매불가] 뱃지와 "공급범위가 변경되어 구매할 수 없습니다." 사유를 표시한다. [품절]과 [구매불가]는 한 품목에 함께 표시할 수 있으며, 뱃지는 상품명 아래 줄에 표시한다.
- 도매노출여부가 미노출이 되거나 삭제된 상품은 구매불가 안내 없이 장바구니를 조회하는 시점에 장바구니에서 제거한다. 품절과 미노출이 동시에 걸린 상품은 미노출 기준으로 제거한다.
- 공급자 그룹에 품절 또는 구매불가 품목이 하나라도 있으면 그 그룹의 [전체주문]은 비활성화되고, [선택상품주문]은 선택한 품목에 품절 또는 구매불가가 포함된 경우 비활성화된다. 다른 공급자 그룹의 주문 버튼에는 영향이 없다. 해당 품목을 삭제하거나 선택에서 제외하면 나머지 품목은 주문할 수 있으며, 그룹 하단에 별도 안내 문구는 두지 않는다.
- 재고 부족(주문 수량이 도매 가용재고를 초과)은 장바구니에 뱃지로 표시하지 않고 주문 생성 시점에만 검증한다.
- 장바구니·주문서 진입 이후 재고와 노출 상태가 바뀔 수 있으므로 주문 생성(주문 완료) 시점에 품목별로 다시 검증한다. 품절 품목이 있으면 "품절상품이 존재합니다.", 구매불가 품목이 있으면 "구매불가 상품이 존재합니다.", 품절·구매불가는 아니지만 주문 수량이 현재 도매 가용재고를 초과하는 품목이 있으면 "재고가 부족한 상품이 있습니다."를 안내하고 주문을 생성하지 않는다. 여러 경우가 겹치면 품절 → 구매불가 → 재고 부족 순으로 하나의 문구만 안내한다.

### 주문서 작성 화면의 초기값

- 주문자 정보: 상호명은 구매 계정의 사업자 정보에 등록된 상호명이며 조회 전용이다. 이름·휴대폰번호·이메일의 초기값은 구매 계정의 회원정보에 등록된 이름·휴대폰번호·이메일이다. 주문서에서 수정할 수 있으며, 수정한 값은 해당 주문에만 저장하고 회원정보는 바뀌지 않는다.
- 배송 정보: 배송지는 `등록된 사업장 주소`(기본 선택)와 `직접입력` 중에서 고른다. `등록된 사업장 주소`는 구매 계정의 사업자 정보에 등록된 사업장 주소이며 주문서에서 수정할 수 없다(조회 전용). `직접입력`은 우편번호 검색으로 기본주소를 채우고 상세주소를 입력한다.
- 입금자명: 계좌이체를 고르면 입력하며 초기값은 5-1절을 따른다.

## 5. 결제 방식과 금액 구성

### 5-1. 결제수단

| 결제수단 | 생성 시 결제상태 | 비고 |
| --- | --- | --- |
| 카드결제 | 결제완료(즉시) | — |
| 계좌이체 | 결제대기 | 입금자명 필수 입력(초기값은 구매 계정의 회원정보 > 계좌정보에 등록된 예금주명이며 주문서에서 수정할 수 있다). 공급자가 결제확인 처리해야 결제완료로 전환된다. |

### 5-2. 배송비

| 항목 | 내용 |
| --- | --- |
| 설정 단위 | 상품마다 설정하지 않는다. 공급자(본인 계정) 1명당 배송방식 설정 1개만 존재하며, 도매설정 화면에서 관리한다. |
| 배송방식 3종 | 무료배송 / 기본배송비(금액 직접입력) / 착불 중 하나만 선택한다. 기본배송비 금액은 미입력 시 0으로 저장한다. |
| 적용 범위 | 해당 공급자가 등록하는 모든 도매상품에 예외 없이 이 설정값이 그대로 적용된다. 상품별 개별 배송비 설정은 없다. |
| 주문(그룹) 단위 산정 | 기본배송비 공급자 그룹은 주문 건당 설정 금액을 1회 가산한다. 무료배송·착불 공급자 그룹은 결제금액에 배송비를 0원으로 반영한다(착불은 배송 시 택배사에 별도로 지불). |
| 주문 스냅샷 | 주문 생성 시점의 배송방식과 배송비 금액을 주문에 함께 저장한다. 이후 공급자가 도매설정의 배송방식·배송비를 변경해도 이미 생성된 주문의 배송비 표기와 금액은 바뀌지 않는다. |
| 주문 화면 표기 | 장바구니 그룹 요약·주문서 결제금액 요약·주문상세·취소·반품 처리 팝업에서 기본배송비(0,000원) / 무료배송(0원) / 착불(별도부과)로 동일하게 표기한다. |
| 상품 화면 표시 | 도매상품등록·상세·수정 화면과 도매상품 주문하기(구매자) 상세 화면 모두 "배송방식" 항목으로 조회 전용 노출한다. |

### 5-3. 카드결제 수수료

| 항목 | 내용 |
| --- | --- |
| 부담 주체 | 공급자별로 구매자부담 또는 공급자부담 중 하나를 도매설정 화면에서 설정한다. |
| 수수료율 | 공급자별로 %로 설정한다. 구매자부담 설정일 때만 입력란이 노출되며, 미입력 시 0으로 저장한다. |
| 결제금액 반영 | 결제수단이 카드이고 해당 공급자 설정이 구매자부담일 때만 (상품금액+배송비) × 수수료율을 결제금액에 가산한다. 계산 결과는 원 단위로 반올림한다(소수점 이하 반올림). 계좌이체는 수수료가 발생하지 않으며, 공급자부담 설정에서는 구매자 결제금액에 반영되지 않는다. |
| 주문 스냅샷 | 주문 생성 시점의 카드수수료 부담 주체·수수료율·수수료 금액을 주문에 함께 저장한다. 이후 공급자가 도매설정의 부담 주체·수수료율을 변경해도 이미 생성된 주문의 수수료 표기와 금액은 바뀌지 않는다. |
| 환불 처리 | 카드결제는 전체환불로 고정되어 총 결제금액 전액을 환불하므로, 구매자부담 수수료도 함께 환불된다. 수수료를 별도로 계산하는 환불 산식은 두지 않는다. |
| 매출 반영 | 구매자부담 수수료는 실제 결제금액에 포함되므로 매출조회 결제총액에 포함되고, 환불 시 취소·환불액에도 포함된다. |
| 정산 | 공급자부담 수수료는 실제 결제금액 안에 포함된 PG 수수료로, 정산은 페이앱에서 처리하는 영역이며 이 시스템의 관리 범위가 아니다. |

### 5-4. 최종 결제금액 구성

`결제금액 = 상품금액 합계 + 배송비(5-2) + 카드수수료(5-3, 구매자부담·카드결제일 때만)`

### 5-5. 도매설정 필수값

도매설정에는 필수 입력 항목이 없어 라벨에 `*`를 표기하지 않는다. 카드결제 수수료 부담 주체·배송방식은 기본 선택값이 있는 라디오 선택이며, 수수료율·기본배송비 금액은 미입력 시 0으로 저장한다. 기본배송비는 0원 이상의 정수, 수수료율은 0 이상 100 미만의 수로 입력한다(범위를 벗어나면 저장되지 않는다). 오류 문구: 기본배송비 "기본배송비는 0원 이상의 정수로 입력해주세요." / 수수료율 "수수료율은 0 이상 100 미만의 숫자로 입력해주세요." 공급범위(우리지역) 설정도 필수가 아니며 등록하지 않아도 저장할 수 있다(규칙은 `09SCM관리자_도소매상품관리_정책정리안` 8-2절).

## 6. 주문상태 전이 (권한별)

주문상태는 주문접수 → 배송대기 → 배송중 → 배송확정 순으로 진행한다(취소·반품 분기는 7절).

| 현재 상태 | 구매자가 할 수 있는 것 | 공급자가 할 수 있는 것 |
| --- | --- | --- |
| 주문접수 | 즉시취소(카드결제·결제대기 건) 또는 취소요청(계좌이체 결제완료 건) | 배송대기 처리 / 취소처리(직권) |
| 배송대기 | 없음(조회만) | 배송중 처리 / 되돌리기(주문접수) / 취소처리(직권) |
| 배송중 | 반품요청, 배송확정 | 되돌리기(배송대기) / 반품처리(직권) / 배송확정 |
| 배송확정 | 없음(종결) | 없음(종결) |

- 공급자의 처리상태 변경은 다음단계 버튼으로 주문접수 → 배송대기 → 배송중 순서대로 한 단계씩만 진행한다(단계를 건너뛸 수 없다). 배송확정은 배송중 단계에서 별도 확인 팝업을 거쳐 처리하며, 배송확정 후에는 되돌릴 수 없다.
- 결제확인(결제대기→결제완료)은 위 처리상태 변경과 완전히 독립된 조작이다. 결제확인을 하더라도 처리상태는 바뀌지 않는다.
- 배송확정은 구매자·공급자 양쪽 모두 처리할 수 있다(대리 처리 허용). 배송확정 처리 시점에 결제상태가 아직 결제대기라면, 결제상태도 함께 결제완료로 자동 전환된다.
- 자동 배송확정: 처리상태가 배송중으로 전환된 일시(처리시점)로부터 7일이 지나면 시스템이 자동으로 배송확정한다. 결제상태가 결제대기이면 함께 결제완료로 전환되고, 결제완료 일시는 자동 배송확정 일시로 기록한다. 처리시점이 갱신되면 자동 배송확정 예정일시도 다시 계산한다. 공급자가 배송중에서 다른 단계로 되돌렸다가 다시 배송중으로 전환한 건과 반품요청이 반려되어 배송중으로 복귀한 건은 해당 시점부터 7일을 다시 센다.
- 자동 배송확정 알림: 자동 배송확정 시 구매자·판매자 모두에게 배송확정 알림을 발송한다(`09SCM관리자_시스템관리_알림설정_정책정리안` 5-6절).
- 처리상태는 가장 최근에 전환된 일시(처리시점)를 함께 저장하며, 다음단계·일괄변경·되돌리기·배송확정(구매자·공급자 처리, 자동 배송확정)·반려 복귀로 처리상태가 바뀔 때마다 갱신한다.
- 주문상세 배송 정보 영역의 처리상태는 `[처리상태] 처리시점` 한 줄로 표기한다. 배송중인 동안에는 `[배송중] 26.09.15 10:00 (26.09.22 10:00 자동배송확정)`처럼 자동 배송확정 예정일시를 함께 표기하고, 배송확정 건은 `[배송확정] 일시`로 표기한다. 배송확정 처리 주체(구매자·공급자 처리 / 자동)는 구분 표기하지 않는다. 취소·반품이 진행 중이거나 종결되어 처리상태가 비워진 건은 "-"로 표시한다.
- 배송확정된 주문의 상품은 이후 소매관리 > 상품관리 > 상품목록에서 소매정보등록 대상이 된다. 소매정보는 주문 단위가 아니라 상품(코드) 단위로 만들며, 배송확정 시 구매자의 도매주문상품 보유수량(계정 + 상품코드 단위)이 구매 수량만큼 증가하며, 같은 상품을 다시 구매(배송확정)하면 누적된다(`09SCM관리자_도소매상품관리_정책정리안` 2-4절).
- 배송대기 단계에 구매자용 취소·반품 요청 화면이 없는 것은 무분별한 취소요청을 막기 위한 의도된 설계다. 공급자는 구매자 요청 여부와 무관하게 이 단계에서도 취소처리(직권)를 할 수 있어야 한다.

### 6-1. 결제완료 일시

| 결제수단 | 결제완료 일시 기록 시점 |
| --- | --- |
| 카드결제 | 주문 생성 시점 |
| 계좌이체 | [결제확인] 처리 시점, 또는 결제확인 없이 배송확정되어 결제완료로 자동 전환된 시점 |

- 결제완료 일시는 매출조회 결제총액의 기준일이다. 주문상세 결제정보에는 결제일시 항목을 따로 두지 않고 결제상태에 `[상태] 일시` 형식으로 함께 표기한다(아래 결제상태 표기).
- 주문상세 결제상태 표기(저장은 결제완료 일시와 취소·반품 승인 일시를 별도로 유지하고, 표기만 상태에 따라 달라진다):
  - 결제대기: `[결제대기]` (일시 없음)
  - 결제완료: `[결제완료] 결제완료 일시`
  - 결제취소(결제대기 상태에서 취소, 환불 없음): `[결제취소] 취소·반품 승인 일시`
  - 결제취소(환불 있음): `[결제취소] 전체환불|부분환불 취소·반품 승인 일시 (결제완료 일시 결제완료)`
- 결제대기 상태로 취소된 주문은 결제완료 일시가 없으므로 매출조회에 집계되지 않는다.
- 결제취소로 전환되어도 결제완료 일시는 삭제하지 않고 보존한다. 결제총액은 결제상태가 아니라 결제완료 일시가 기간 내인지로 집계하며, 취소·환불액은 별도로 차감한다.
- 취소·반품 승인 일시는 카드결제는 페이앱 결제취소 성공 응답을 확인한 일시(페이앱 응답에 취소일시 값이 없어 시스템 기록 시점을 사용), 계좌이체는 취소·반품을 승인한 일시다. 결제취소가 아닌 건에는 표기하지 않는다.

### 6-1-1. 결제상태 값과 결제취소

- 결제상태 값은 결제대기/결제완료/결제취소 3종이다. 결제취소는 취소·반품승인이 확정될 때 전환되는 종결 상태이며, 결제대기 상태에서 취소·반품승인된 건도 결제취소로 전환한다(구매자 즉시취소 포함). 별도의 [결제취소] 버튼은 두지 않으며 진입점은 [취소처리]·[반품처리]·조정 모드 승인·구매자 즉시취소뿐이다.
- 카드결제 건은 [승인] 시 페이앱에 결제취소를 요청하고, 성공 응답을 확인한 뒤에만 취소·반품승인을 확정한다(결제상태 결제취소·재고 반영·알림 발송도 이 시점). 결제취소가 실패하면 승인은 확정되지 않고 요청 상태를 유지하며 실패 안내 후 재시도한다. 계좌이체·현장결제 건은 승인 즉시 결제취소로 전환하고 환불 이행은 판매자가 직접 처리한다(결제취소는 취소 처리 확정을 뜻하며 환불 이행 완료를 의미하지 않는다). 페이앱 응답 지연·미수신 시 처리 방식은 개발 확인이 필요하다.
- 결제취소 건은 환불구분(전체환불/부분환불)을 표시한다(주문접수관리·주문내역 목록, 주문상세 결제정보). 결제대기 상태에서 취소된 건은 환불이 없으므로 표시하지 않는다.
- 일시·날짜·기간 표기 형식은 디자인시스템 문서의 "날짜·일시 표기"를 따른다.

### 6-2. 관리 버튼(주문접수관리 목록·주문상세 공통)

버튼 이름에 "~으로"를 붙이지 않고 이동할 단계명을 그대로 쓴다.

| 처리상태 | 다음단계 | 결제확인 | 취소·반품처리 | 되돌리기 |
| --- | --- | --- | --- | --- |
| 주문접수 | [배송대기] | 결제대기일 때(목록·상세) | [취소처리] | 없음 |
| 배송대기 | [배송중] | 결제대기일 때(목록·상세) | [취소처리] | 주문접수로 복귀 |
| 배송중 | [배송확정](확인 팝업), 결제대기이면 [결제·배송확정] | 결제대기일 때(상세에서만) | [반품처리] | 배송대기로 복귀 |
| 배송확정 | 없음 | 없음 | 없음 | 없음 |
| 취소요청 · 반품요청 | 없음 | 없음 | [취소처리] 또는 [반품처리](조정 모드 팝업) | 없음 |
| 취소승인 · 반품승인 | 없음 | 없음 | 없음(상세에 "처리 완료된 주문입니다." 안내) | 없음 |

- 되돌리기는 직전 단계로만 복귀한다. 클릭 즉시 반영하고 확인 팝업은 없다. 되돌리면 처리시점이 되돌린 시점으로 갱신되고, 다시 배송중으로 전환하면 그 시점부터 자동 배송확정 7일을 다시 계산한다.
- 배송확정, 취소·반품요청, 취소·반품승인 상태에서는 되돌리기를 제공하지 않는다. 취소·반품요청은 처리 팝업에서 반려하면 요청 이전 상태로 복귀하고, 승인되면 주문 처리 단계에서 빠져 더 이상 처리할 수 없다.
- 결제확인은 결제상태만 바꾸며 처리상태는 바뀌지 않는다.
- 목록의 [결제확인]은 처리상태가 주문접수·배송대기인 결제대기 건에만 노출한다. 배송중 단계의 결제대기 건은 [결제·배송확정]으로 결제와 배송확정을 함께 진행하므로 목록에 [결제확인]을 노출하지 않고 주문상세에서만 처리한다.
- [결제·배송확정]은 배송중 단계이면서 결제상태가 결제대기인 주문의 배송확정 버튼 명칭이다. 확인 팝업에서 배송확정 처리와 함께 결제상태도 결제완료로 전환된다.
- 배송확정 처리(구매자·공급자 처리, 자동 배송확정 모두) 시점에 결제상태가 결제대기이면 결제완료로 자동 전환되므로, 배송확정 이후에는 결제대기 건이 존재하지 않아 결제확인 버튼을 제공하지 않는다. 결제대기가 남을 수 있는 처리상태는 주문접수·배송대기·배송중(계좌이체 주문)이다.

### 6-2-1. 주문접수관리 목록 조회

- 구매자 정보 컬럼·검색 명칭은 "주문자"로 표기한다(소매 주문목록과 같은 명칭)(컬럼 "주문자", 검색 "주문번호, 주문자명, 상품명 검색" — 주문번호·주문자명·주문상품명 중 하나라도 일치하면 조회). 도매 "주문자"의 값은 구매 계정의 사업자정보 상호명이다(주문서에 입력한 담당자 이름이 아니다). 주문서 작성 화면과 주문상세의 "주문자 정보"는 같은 구조로 상호명(구매 계정의 사업자정보 값, 조회 전용)·이름·휴대폰번호·이메일을 표시하며, 이름·휴대폰번호·이메일은 주문서에 입력한 담당자 정보다.
- 취소·반품 처리 주체 표기("구매자 요청", "구매자 즉시취소")는 역할 구분을 위한 명칭이다.
- 2차 탭은 전체/결제대기/결제완료/결제취소/반려(취소반려·반품반려 통합)이며, 1차 탭 선택과 별개로 목록 전체에 동시 적용되는 필터다(취소·반품요청/승인 1차 탭에서도 동일하다). 1차 탭을 변경하면 2차 탭은 전체로 초기화된다.

### 6-2-2. 페이지네이션(주문접수관리·주문내역)

- 주문접수관리와 주문내역(구매자)은 페이지당 20건이며 목록 페이지네이션은 디자인시스템 문서의 "목록 페이지네이션·건수 표시 표준"을 따른다.
- 주문접수관리의 일괄변경 대상은 현재 페이지에서 선택한 건에 한정하고 페이지를 이동하면 선택이 해제된다. 일괄변경 확인 창에는 선택한 건수와 처리 가능 건수를 표시한다.

### 6-3. 일괄변경(주문접수관리 목록)

- 체크박스로 주문을 선택하고(헤더 체크박스로 전체 선택), 처리 셀렉트에서 처리를 고른 뒤 [일괄변경]을 누른다. 현재 페이지에서 선택한 건만 대상이다.
- 셀렉트 옵션은 배송대기 / 배송중이다. 배송확정과 취소·반품처리는 확인 팝업과 사유·환불 입력이 필요하므로 일괄변경 대상에서 제외한다. 결제확인은 일괄변경 대상이 아니며 목록·상세의 [결제확인]으로 건별 처리한다.
- 선택한 주문 중 아래 조건을 만족하는 건만 반영하고 나머지는 변경 없이 제외한다.

- 전체 반영 가능·일부만 반영 알럿에 "도매구매 알림이 설정된 경우 알림이 발송될 수 있습니다." 안내를 함께 표시한다. 도매 구매자에게는 알림톡이 아닌 시스템 알림(도매구매 카테고리)이 발송되므로 소매의 "고객 알림톡" 문구와 구분해 알림 카테고리명으로 표기한다.
- 처리 완료 후 선택은 해제된다.

## 7. 취소·반품 규칙

### 7-1. 요청 가능 시점 (구매자 기준)

| 구분 | 요청 가능 조건 |
| --- | --- |
| 즉시취소 | 주문접수 단계이고 취소·반품 이력이 없는 카드결제 건 또는 결제대기 건. 구매자 주문내역의 [주문취소] 버튼과 확인 팝업으로 처리하며 공급자 승인 없이 취소승인으로 확정된다 |
| 취소요청 | 주문접수 단계이고 취소·반품 이력이 없는 계좌이체 결제완료 건(환불이 공급자 수동 처리라 승인 요청으로 진행). 구매자 주문내역의 [취소요청] 버튼으로 요청한다 |
| 반품요청 | 배송중 단계이고 취소·반품 이력이 없을 때(배송중 전환 후 7일 이내 — 7일 경과 시 자동 배송확정되어 요청 불가) |

- 취소는 배송 시작 전(주문접수), 반품은 배송 시작 후(배송중)로 시점이 구분된다.
- 계좌이체 건은 요청 시 환불은행·예금주·환불계좌번호와 요청 사유를 필수 입력해야 한다(라벨에 `*` 표기). 카드결제 건은 승인 시 페이앱을 통해 결제가 취소되므로 환불계좌를 입력받지 않고, 요청 사유만 필수다.
- 구매자가 요청 시 입력한 환불계좌 정보는 공급자 처리 화면(7-4)에 자동으로 채워지되, 공급자가 처리 시점에 다시 수정할 수 있다.

**구매자 즉시취소 처리**

- 처리 결과는 취소승인이며 처리 주체는 "구매자 즉시취소"로 기록한다. 처리상태는 비워지고 공급자 주문접수관리에서는 취소·반품승인 그룹에 표시되며, 공급자가 처리할 조작은 없다.
- 공급자 보유수량은 자동 복원된다(재고 반영 체크박스 없음). 카드 결제완료 건은 결제가 전액 취소(총환불금액 = 총 결제금액)되고 결제상태가 결제취소로 전환되며, 결제대기 건은 환불 없이 결제취소로 전환된다.
- 공급자에게는 시스템 알림 "취소/반품 접수"(즉시취소형 문구)가 발송된다(`09SCM관리자_시스템관리_알림설정_정책정리안`). 구매자 본인이 처리한 건이므로 도매구매 알림은 발송하지 않는다.
- 카드 결제취소(페이앱)가 실패하면 취소는 처리되지 않고 주문은 기존 상태를 유지하며, 구매자가 다시 시도한다(별도 예외 처리 없음). 결제취소 성공 응답을 확인한 뒤에만 취소승인이 확정된다.

### 7-2. 처리 방식 (공급자 기준)

| 구분 | 조정 모드 (구매자 요청이 있는 건) | 직권 모드 (요청 이력 없음, 또는 반려로 종료된 건) |
| --- | --- | --- |
| 가능 시점 | 요청이 들어온 단계에 한정(주문접수=취소요청, 배송중=반품요청) | 주문접수·배송대기 단계=취소처리만 / 배송중 단계=반품처리만 |
| 처리 방식 | 승인/반려 2지선다 라디오 중 선택(기본값: 승인) | 별도 상태 선택(라디오) 없이 제출 즉시 승인 처리 |
| 승인 시 | 주문 흐름이 종료된다. 환불 영역(7-4)과 재고 반영 체크박스가 노출된다 | 동일 — 팝업 진입 시점부터 환불 영역이 노출된다 |
| 반려 시 | 주문상태가 이전 단계로 복귀한다(취소반려→주문접수, 반품반려→배송중). 환불 영역과 재고 반영 체크박스는 노출되지 않는다 | 해당 없음 |

- 취소승인·반품승인으로 종결된 건은 이후 어떤 처리도 되지 않는다.
- 직권 모드로 승인 처리된 건은 공급자가 구매자 요청 없이 임의로 처리했음을 구분해 별도로 기록한다.
- 처리할 때마다 처리상태와 처리 일시를 갱신한다(최근 1건만 표시). 승인으로 종결된 건은 이 일시가 매출조회 취소·환불액의 기준일(취소·반품 승인 일시)이 된다.

### 7-3. 재고 반영과의 연결

취소·반품이 승인으로 확정되는 시점에만 재고 반영 여부를 공급자가 체크박스로 선택할 수 있으며(기본값: 선택), 체크된 경우 해당 주문 전체 품목 수량만큼 공급자 본인 보유수량을 복원한다. 복원할 대상(내 도매상품)이 주문 품목 중 하나도 없으면(상품 삭제 등) 체크박스 자체를 노출하지 않는다. 세부 규칙은 `09SCM관리자_도소매상품관리_정책정리안`을 따른다.

### 7-4. 취소·반품 처리 팝업 구성

소매주문처리(`09SCM관리자_소매주문처리_정책정리안` 5절)와 동일한 구성을 사용하며, 환불 입력 방식만 결제수단 구성에 맞게 다르다.

| 블록 | 구성 |
| --- | --- |
| 제목 | 취소처리 / 반품처리 |
| 처리 정보 | 처리 주체("공급자 직권" 또는 "구매자 요청" — 변형 표기를 쓰지 않는다) / 결제수단 / 결제상태 (조회 전용). 도매는 수령방식 항목이 없다 |
| 처리 방식 | 승인/반려 라디오 — 조정 모드에만 노출(직권 모드는 미노출) |
| 금액 조회 | 상품금액 / 배송비(배송방식 표기) / 결제수수료(구매자부담 카드결제일 때만) / 총 결제금액 — 조회 전용 |
| 환불 입력 | 환불구분 / (부분환불 시) 상품환불금액·배송비 포함 / 총환불금액 / 환불 방법(아래 표) |
| 사유·재고 | 구매자 요청 사유(요청이 있는 건만, 조회 전용) / 공급자 처리 사유(자유 텍스트) / 재고 반영 체크박스(7-3) |
| 버튼 | [닫기] [취소처리 또는 반품처리] |

- 금액 조회·환불 입력 블록은 승인일 때만 노출되며, 조정 모드에서 반려를 선택하면 두 블록과 재고 반영 체크박스를 숨긴다.

**환불 입력 (결제수단별)**

| 항목 | 카드결제 | 계좌이체 |
| --- | --- | --- |
| 환불구분 | 전체환불 고정(부분환불 선택 불가, 비활성) | 전체환불(기본) / 부분환불 선택 |
| 전체환불 | 총환불금액 = 총 결제금액, 수정불가. 안내: "총 결제금액(배송비+상품금액+결제수수료)" — 공급자부담이면 "(배송비+상품금액)" | 총환불금액 = 총 결제금액, 수정불가. 안내: "총 결제금액(배송비+상품금액)" |
| 부분환불 | 해당 없음 | 상품환불금액 입력(0원 이상, 상품금액 이내) + "배송비 포함 (0,000원)" 체크박스(기본 선택) → 총환불금액 = 상품환불금액 + 체크 시 배송비, 수정불가 |
| 환불 방법 | 안내: "카드결제 건은 승인 시 PG사를 통해 자동으로 결제가 취소됩니다." 환불계좌 입력 없음 | 환불은행 / 예금주 / 환불계좌번호 입력(필수 아님, 구매자 입력값 자동 채움·수정 가능) |

- 무료배송·착불 건은 배송비가 결제금액에 0원으로 반영되어 있으므로 "배송비 포함" 체크박스를 노출하지 않는다.
- 총환불금액이 0원이면 처리 버튼을 비활성화하고 "환불금액을 입력해주세요." 오류 문구를 노출한다.
- 결제상태가 결제대기인 건은 결제된 금액이 없으므로 금액 조회·환불 입력 블록(금액 조회·환불구분·총환불금액·환불계좌)을 모두 노출하지 않고, "결제 대기 중인 주문으로 환불은 진행되지 않습니다." 안내 1블록만 노출한다. 승인해도 환불값을 저장하지 않고 결제상태만 결제취소로 전환한다. 카드결제는 즉시 결제완료이므로 이 경우는 계좌이체에서만 발생한다.

### 7-5. 환불 저장값과 주문상세 표시

- 승인 시 환불구분과 총환불금액을 저장한다. 매출조회의 취소·환불액은 총환불금액만 합산한다.
- 부분환불 건은 총환불금액의 구성(상품환불금액, 배송비 환불 포함 여부)을 함께 저장한다.
- 주문상세의 취소·반품 정보 영역에 환불구분과 총환불금액을 표시하고, 부분환불 건은 상품환불금액과 배송비 환불 포함 여부를 함께 표시한다.

## 9. 도매매출조회 화면구성

- [엑셀 다운로드] 버튼을 제공한다. 현재 화면의 조회 기간 기준 매출 요약(결제총액/취소·환불액/매출액)과 현재 선택된 매출 추이(일별/월별) 상세 내역 표 전체를 엑셀 파일로 내려받는다.
- 화면 진입 조건: 로그인 계정이 도매공급권한을 보유한 경우에만 LNB에 노출되는 메뉴다. 화면 자체에는 공급자 선택과 같은 필터를 두지 않는다 — 이 메뉴 자체가 이미 로그인 계정(공급자) 본인 기준으로만 접근·집계되는 화면이기 때문이다.
- 기간 필터: 오늘/이번주/이번달/기간(직접 선택) 4가지를 제공하며 기본값은 이번달이다. 개월 단위 필터는 두지 않는다. 기간 직접 선택은 시작일 기준 최대 6개월까지 선택할 수 있으며, 종료일 선택 범위를 시작일 + 6개월 이내로 제한하고 "매출 조회 기간은 최대 6개월까지 선택할 수 있습니다." 문구를 함께 안내한다. 기간 필터는 매출 요약과 매출 추이(차트·상세 내역 표)에 모두 적용한다.
- 매출 요약: 결제총액 / 취소·환불액 / 매출액 3개 항목으로 구성한다. 소매매출조회와 동일한 산식·기준일을 사용한다.

| 항목 | 산식 | 기준일 |
| --- | --- | --- |
| 결제총액 | 총 결제금액(상품금액+배송비+구매자부담 카드수수료) 합계 | 결제완료 일시가 기간 내인 주문(이후 결제취소로 전환된 건 포함) |
| 취소·환불액 | 총환불금액 합계 | 상태가 취소승인·반품승인이고 취소·반품 승인 일시가 기간 내인 주문. 카드결제 건은 페이앱 결제취소 성공 응답을 확인한 일시. 결제대기 취소 건은 환불이 없어 제외 |
| 매출액 | 결제총액 − 취소·환불액 | — |

- 결제일과 취소일이 다른 기간에 속하면 결제총액과 취소·환불액이 서로 다른 기간에 집계되며, 기간에 따라 매출액이 음수가 될 수 있다.
- 배송비·카드수수료는 별도 항목으로 분리하지 않는다.
- 매출 추이: 일별/월별 탭으로 전환 가능한 차트(매출액 기준)와, 기간별 상세 내역 표를 함께 제공한다. 상세 내역 표 조회 항목은 기간 / 총주문건수 / 총결제액 / 카드결제 주문건수 / 카드결제액 / 현장결제·계좌이체 주문건수 / 현장결제·계좌이체 결제액 / 취소환불건수 / 취소환불액 / 매출액이며(통합매출조회 추이 표와 동일), 집계 기준일은 항목별로 다르다. 주문건수(총주문건수·카드결제 주문건수·현장결제·계좌이체 주문건수)는 주문접수일 기준, 결제액(총결제액·카드결제액·현장결제·계좌이체 결제액)은 결제완료 일시 기준, 취소환불건수·취소환불액은 취소·반품 승인 일시 기준으로 집계한다. 총주문건수는 기간 내 접수된 전체 주문(카드결제 + 현장결제 + 계좌이체)이며 결제 여부·취소 여부와 무관하다. 표 상단에 "주문건수는 주문접수일, 결제액은 결제완료일, 취소·환불은 승인일 기준으로 집계합니다." 기준 안내를 노출한다. 상세 내역 표는 최신 기간순으로 정렬하고 페이지당 10건씩 페이지네이션을 적용한다.
- 주문 건별 상세 목록은 이 화면에 두지 않는다 — 도매관리 > 주문내역(구매자)/주문접수관리(공급자)에서 이미 조회 가능한 내용을 중복 구성하지 않는다.

## 10. 확인 필요 사항

| 항목 | 내용 |
| --- | --- |
| 본인 상품 구매 제한의 서버 검증 | 본인 상품 구매 제한은 주문 생성 API(서버) 단에서도 검증해야 하며, 검증 방식은 개발 단계에서 확인이 필요하다. |
| 품목별 부분 취소·반품 | 현재는 주문 전체 단위만 지원한다. 한 주문 안에서 일부 품목만 취소·반품하는 처리는 도매·소매 공통 후속 검토 대상이다. |
| 우리지역 시·군·구 판정 | 구매자·공급자 사업장 주소에서 시·군·구를 판정하는 방식(주소 구조화 저장 또는 행정구역 마스터 매칭), 행정구역 개편·명칭 변경, 시·군·구 구분이 없는 지역(세종 등)의 처리는 개발 확인이 필요하다. |
| 계좌이체 결제완료 건 즉시취소 | 환불이 공급자 수동 처리라 현재는 즉시취소 대상에서 제외하고 취소요청(승인)으로 유지한다. 운영 후 구매자 클레임이 발생하면 즉시취소 확대를 재검토한다. |
| 반품요청 7일 기한의 법적 기준 | 구매자 반품요청은 배송중 전환 후 7일 이내로 제한하고 7일이 지나면 자동 배송확정한다. 전자상거래법 청약철회 기준과의 관계는 법무 확인이 필요하다. |
