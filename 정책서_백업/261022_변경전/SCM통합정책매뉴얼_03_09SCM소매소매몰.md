# 1장. 소매몰 설정 (R-MAL)

## 1.1 적용 범위

- 대상 화면: 소매관리 > 소매설정(기본정보 탭, 이용약관·개인정보처리방침 탭)
- 대상 계정: 소매몰을 운영하는 본사·가맹점 계정(각자 자기 소매몰만 설정한다)
- 제외 범위: 메인상품진열(→ 04 파일 W-PRD), 배달 주문 처리(→ 3장 R-ORD)

## 1.2 정의

| 용어 | 정의 |
| --- | --- |
| 소매설정 | 소매몰의 상호·픽업주소·수령방식·배달비·약관을 관리하는 단일 화면 |
| 기본 수령방식 | 소매몰의 판매방식 기본값. 픽업만 / 배달만 / 픽업, 배달 모두 |
| 기본 배달비 | 소매몰 단위 단일 배달비(원). 배달 주문 생성 시 해당 주문의 배달비로 반영한다 |
| 상호정보 상호명 | 소매설정에서 편집하는 소매몰 전용 상호명. 회원정보의 사업자 상호명과 별개 값이다 |

## 1.3 요건

### 가. 기본정보

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-MAL-001 | 기본정보 필수값 검증 | 기본정보 저장 시 상호명, 픽업주소의 우편번호·기본주소, 소매몰명, 기본 수령방식이 비어 있으면 시스템은 저장하지 않고 항목별 오류 문구를 노출한다. 필수 항목은 라벨에 `*`를 표기한다 |
| R-MAL-002 | 소매몰 전용 상호명의 사용처 | 상호정보의 상호명은 소매몰 전용 값이며 알림톡 `#상호명`, 소매몰 메인 매장정보의 "상호", 주문서·주문완료의 "픽업 장소" 상호에 쓴다. 소매몰 푸터를 포함한 그 밖의 상호명은 회원정보 사업자정보의 상호명이다. 사업자정보의 사업자 상호명은 회원정보 값을 보여주는 조회용이며 알림톡 변수에 쓰지 않는다 |
| R-MAL-003 | 상호명·소매몰명 초기값 | 상호명과 소매몰명의 초기값은 가입 시 입력한 회원정보(사업자정보)의 상호명을 불러온다. 이후에는 소매설정에서 수정할 수 있으며 별도 값으로 관리하고 회원정보와 동기화하지 않는다 |
| R-MAL-004 | 사업자정보·계좌정보의 조회 전용 | 사업자 상호명·대표자명·사업자등록번호·사업장 주소와 계좌정보(은행·계좌번호·예금주)는 회원정보 값을 표시하는 조회 전용 항목이며 소매설정에서 수정할 수 없다. 통신판매업 신고번호는 소매설정에서만 입력할 수 있는 유일한 사업자정보 항목이다. 사업자정보는 본사 문의를 통해, 계좌정보는 시스템관리 > 회원정보에서 직접 변경한다 |
| R-MAL-005 | 픽업주소 입력 방식 | 우편번호·기본주소는 "우편번호 검색"으로만 채우는 읽기전용 항목이다. 우편번호·기본주소·상세주소의 초기값은 회원정보(사업자정보)의 값이며 이후 수정할 수 있다. 상세주소는 직접 입력하는 선택 항목이다. 픽업주소는 우편번호·기본주소·상세주소를 이어 붙여 알림톡 `#픽업주소`, 소매몰 메인 매장정보, 주문서·주문완료의 "픽업 장소"에 쓴다 (→ OI-R-01) |
| R-MAL-006 | 소매몰 이미지 등록 제한 | 소매몰로고와 공유 이미지는 각각 이미지 1장, JPG·PNG·WEBP, 파일당 5MB 이하로 등록한다. 공유 이미지가 없으면 시스템 기본 공유 이미지를 노출한다 |
| R-MAL-017 | 소매몰명·로고의 노출 | 소매몰명은 소매몰 상단 헤더의 이름, 브라우저 타이틀, 링크 공유 시 소매몰 이름에 쓴다. 소매몰로고를 등록하면 헤더에서 소매몰명 텍스트 대신 로고 이미지를 표시하고, 등록하지 않으면 소매몰명 텍스트를 표시한다 |

# 2장. 소매몰 회원 관리 (R-MEM)

## 2.1 적용 범위

- 대상 화면: 소매관리 > 회원관리(회원목록, 회원정보 상세, 탈퇴 사유 조회 팝업)
- 대상 계정: 소매몰을 운영하는 본사·가맹점 계정(각자 자기 소매몰 회원만 조회·관리한다)
- 제외 범위: 채팅주문 매칭·도용 판단 운영 규칙(→ 4장 R-CHT), 고객용 소매몰의 가입·로그인·주문 차단 구현(→ 5장 R-CST)

## 2.2 정의

| 용어 | 정의 |
| --- | --- |
| 회원주문 코드 | 회원을 식별하는 숫자 4자리 코드. 채팅주문을 회원과 매칭할 때 조회 키로 쓰며 링크주문 주문자정보에도 표시한다 |
| 채팅주문 닉네임 | 회원이 오픈채팅방에서 실제 쓰는 닉네임. 매칭 시 수신 메시지의 닉네임과 대조해 코드 도용을 판단하는 데 쓴다. 선택 항목이며 등록하지 않은 회원은 채팅주문을 이용할 수 없다 |
| 노쇼 이력 | 회원과 연결된 주문 중 취소·반품 처리주체가 "노쇼 처리"로 기록된 건수 |
| 일반회원 / 탈퇴회원 | 회원목록의 1차 탭. 탈퇴회원은 상세정보 조회가 불가하다 |

소매몰 회원 이용상태(정상 / 이용제한)는 00 공통 3-2를 따른다.

## 2.3 요건

### 가. 회원 식별·연결

| ID | 요건명 | 요건 |
| --- | --- | --- |

| R-MEM-002 | 회원 식별키 | 회원 아이디는 휴대폰번호이며 회원 식별키다. 주문은 이 회원과 연결한다 |
| R-MEM-003 | 휴대폰번호 변경 조건 | 관리자가 회원의 휴대폰번호를 변경하려면 신규 번호의 중복확인과 인증번호(숫자 6자리) 본인확인을 모두 통과해야 한다. 둘 중 하나라도 완료하지 않으면 [저장]을 비활성 상태로 둔다. 저장 시 입력한 번호는 중복확인을 통과한 값과 같아야 한다 |
| R-MEM-004 | 번호 변경 후 주문 연결 | 휴대폰번호를 변경하면 회원 아이디도 변경된 번호로 바뀐다. 기존 주문과의 연결은 유지하며 기존 주문의 주문자 휴대폰번호 표시값은 주문 시점 값 그대로다 |
| R-MEM-005 | 회원주문 코드의 형식·유일성 | 회원주문 코드는 숫자 4자리이며 같은 소매몰 안에서 유일해야 한다. 입력란은 숫자 외 문자를 받지 않고 4자까지만 입력되며, 4자리가 아닌 값으로 중복확인 또는 저장하면 "회원주문 코드는 숫자 4자리로 입력해주세요."로 막는다 |
| R-MEM-006 | 회원주문 코드 변경 조건 | 회원주문 코드를 기존 값에서 바꾸려면 변경한 값으로 중복확인을 먼저 통과해야 한다. 저장 시 입력값은 중복확인을 통과한 값과 같아야 하며 값을 다시 바꾸면 재확인한다. 중복확인은 같은 소매몰의 다른 회원과의 코드 중복만 검사한다. 진행중 주문이 있는 회원도 회원주문 코드를 변경할 수 있다 |
| R-MEM-007 | 회원주문 코드와 주문 연결 | 주문과 회원의 연결은 회원 식별키로 유지하며 회원주문 코드는 연결 키로 쓰지 않는다. 회원주문 코드를 바꿔도 주문 연결·노쇼 이력·주문 이력은 유지한다 |
| R-MEM-008 | 주문자 정보의 스냅샷 | 주문자명(회원명)·휴대폰번호·닉네임은 주문 시점 값으로 보존한다. 이후 회원정보를 바꿔도 기존 주문에 표시되는 값은 바뀌지 않는다 |
| R-MEM-009 | 누적 주문 집계 기준 | 상품주문건수와 주문금액은 결제상태가 결제완료인 주문만 집계하고 취소·반품이 승인으로 확정된 주문은 제외한다(결제대기·결제취소 제외). 주문금액은 해당 주문의 총 결제금액(상품금액 + 배달비) 합계다 |
| R-MEM-010 | 노쇼 이력 집계 | 노쇼 이력은 회원 식별키로 연결된 주문 중 취소·반품 처리주체가 "노쇼 처리"로 기록된 건수이며 조회 전용이다 |
| R-MEM-011 | 회원정보 저장 필수 항목 | 회원정보 저장 시 이름, 이메일, 회원주문 코드 3개 항목이 입력되어 있어야 한다. 채팅주문 닉네임은 필수 항목이 아니며 링크주문만 이용하는 회원은 비워둘 수 있다 |
| R-MEM-012 | 단일 배달지 관리 | 배달지는 회원가입(고객용 프론트)에서 선택 항목으로 1개만 입력할 수 있으므로 단일 배달지(배달지명·배달 주소·배달 요청사항)만 관리한다. 다건 배달지는 지원하지 않으며, 배달지를 입력하지 않은 회원은 배달지가 없는 상태다 |
| R-MEM-023 | 배달지의 관리자 입력·수정 | 관리자는 회원정보 상세에서 회원의 배달지(배달지명·배달 주소·배달 요청사항)를 입력·수정하여 저장할 수 있다. 세 항목을 모두 비우고 저장하면 해당 회원은 배달지가 없는 상태가 된다 |

### 나. 이용상태

| ID | 요건명 | 요건 |

| R-MEM-013 | 이용상태 변경 경로 | 회원 이용상태(정상 / 이용제한)는 회원정보 상세에서만 변경하며 회원목록에서는 조회만 한다. 이용상태를 라디오로 선택하고 [변경]을 눌러야 적용한다. 선택값을 바꾸는 것만으로는 반영하지 않으며, 선택값이 현재 이용상태와 같으면 [변경]을 비활성화한다. 적용 결과는 [변경] 옆에 "처리되었습니다."로 안내한다 |
| R-MEM-014 | 이용상태 전환 조건 | 정상 ↔ 이용제한 전환은 진행중 주문 여부와 관계없이 할 수 있다 |
| R-MEM-015 | 이용제한 회원의 차단 범위 | 이용제한 회원은 채팅주문과 링크주문 모두 신규 주문을 할 수 없고 소매몰에 로그인할 수 없다. 차단 처리는 고객용 소매몰과 주문 생성 로직에서 구현하며 이 관리자 화면은 상태값의 표시·변경까지 다룬다 |
| R-MEM-016 | 이용제한 회원의 채팅주문 매칭 | 채팅주문 매칭 화면에서 매칭 대상 회원이 이용제한이면 "이용제한 회원 — 매칭 적용 시 주문접수가 제한됩니다" 경고를 노출하고 매칭 적용(제출) 시점에 차단한다 (→ 4장 R-CHT) |

### 다. 탈퇴·삭제

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-MEM-017 | 탈퇴 처리 조건 | 탈퇴 처리는 회원정보 상세의 [탈퇴 처리] 팝업에서 한다. 탈퇴 처리 사유는 필수다. 확정하면 회원 상태가 탈퇴로 전환되고 탈퇴일시를 자동 기록하며 입력한 사유를 저장한다. 처리 즉시 회원목록(탈퇴회원 탭)으로 이동한다 |
| R-MEM-018 | 탈퇴회원 상세 접근 차단 | 탈퇴회원은 회원정보 상세 페이지에 진입할 수 없다. 탈퇴회원의 회원 id로 진입하면 회원목록(탈퇴회원 탭)으로 되돌린다 |
| R-MEM-019 | 탈퇴회원 노출 제한 | 탈퇴회원은 개인정보처리방침상 상세정보 조회가 불가하므로 목록에서 회원명·휴대폰번호·탈퇴일시만 노출한다. 상세 페이지 대신 탈퇴 사유 조회 팝업(읽기전용, 회원명·휴대폰번호·탈퇴일시·탈퇴 사유만 표시)만 제공한다 |
| R-MEM-020 | 탈퇴회원 삭제 | 삭제는 탈퇴회원에게만 할 수 있으며 일반회원에는 삭제 버튼이 없다. 진행중 주문 여부에 따른 차단은 없다. 삭제는 완전 삭제이며 복원할 수 없다. 일괄삭제는 현재 페이지에서 선택한 건에 한정하며 페이지를 이동하면 선택이 해제된다 |
| R-MEM-021 | 삭제 회원의 주문내역 | 삭제한 회원의 기존 주문내역은 주문 당시 정보(스냅샷)로 남으며 주문 진행에는 영향을 주지 않는다 (→ OI-R-02) |
| R-MEM-022 | 탈퇴 후 재가입 | 탈퇴한 회원과 같은 번호로 재가입할 수 있다. 중복확인(휴대폰번호·회원주문 코드) 판정에서 탈퇴회원은 제외하므로 탈퇴회원이 쓰던 번호·코드는 다른 회원이 쓸 수 있다. 재가입 회원은 별개의 신규 회원이며 탈퇴회원의 정보(회원주문 코드·채팅주문 닉네임·배달지 등)를 이어받지 않고 이전 주문과도 연결하지 않는다. 재가입 처리는 고객용 소매몰의 가입 로직에서 구현한다 |

> **경고** 탈퇴 처리와 삭제는 복원할 수 없다. 탈퇴 처리 팝업에는 "탈퇴 처리된 회원의 정보는 복원할 수 없습니다. 신중하게 처리해주세요."를, 삭제 확인 창에는 "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요."를 노출한다.

> **주의** 회원주문 코드와 휴대폰번호는 서로 다른 키다. 주문 연결은 휴대폰번호로 식별되는 회원으로 유지하고 회원주문 코드는 채팅주문 매칭용 조회 키다.

# 3장. 소매 주문 처리·소매매출조회 (R-ORD)

## 3.1 적용 범위

- 대상 화면: 소매관리 > 주문관리(주문목록, 주문상세), 소매매출조회
- 대상 계정: 소매몰을 운영하는 본사·가맹점 계정(공급자 관점 단일 화면). 구매자는 관리자 계정이 아닌 소매몰 회원이다
- 제외 범위: 채팅주문 접수·매칭(→ 4장 R-CHT), 소비자의 주문내역·취소요청·반품요청 화면(→ 5장 R-CST), 도매 주문(→ 04 파일 W-ORD), 알림 발송 기준(→ 02 파일 A-NTF)
- 결제내역 메뉴는 두지 않는다. 결제확인·완료 처리·취소·반품 처리 등 결제 관련 처리를 모두 주문목록·주문상세에서 하기 때문이다

## 3.2 정의

| 용어 | 정의 |
| --- | --- |
| 주문경로 | 링크주문 / 채팅주문. 접수 이후 처리는 공통이다 |
| 진행 단계 / 완료 단계 | 픽업은 주문접수·픽업대기 / 픽업완료, 배달은 주문접수·배달대기·배달중 / 배달완료 |
| 공통 픽업가능기간 | 주문 시점에 주문 품목들의 픽업가능기간이 겹치는 기간(시작일~종료일)을 주문에 저장한 값 |
| 조정 모드 | 이미 취소요청·반품요청 상태인 건을 승인/반려로 처리하는 방식 |
| 직권 모드 | 요청 이력이 없거나 반려로 종료된 건을 공급자가 바로 처리하는 방식 |
| 구매자 즉시취소 | 주문접수 단계에서 구매자가 카드결제·결제대기 건을 직접 취소해 판매자 승인 없이 취소승인으로 확정되는 처리 |
| 처리시점 | 처리상태가 가장 최근에 전환된 일시 |
| 총 결제금액 | 상품금액 + 배달비(배달 주문만) |

처리상태, 결제상태, 취소·반품 상태, 노쇼후보, 환불구분, 기준일시, 판매가능수량·보유수량은 00 공통 3-3~3-5를 따른다.

## 3.3 요건

### 가. 주문 생성 조합

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-ORD-001 | 주문경로별 처리 공통 | 링크주문과 채팅주문은 같은 주문 데이터 구조에 저장하며 접수 이후 화면·처리를 공통으로 쓴다 |
| R-ORD-002 | 수령방식별 결제수단 | 픽업 주문은 카드결제·계좌이체·현장결제가 모두 가능하다. 배달 주문은 카드결제만 가능하며 항상 선결제이므로 생성 시점부터 결제상태를 결제완료로 고정한다. 배달비는 배달 주문에만 있다 |
| R-ORD-003 | 채팅주문의 조합 | 채팅주문은 항상 픽업과 현장결제 조합이며 결제대기·주문접수로 생성한다. 한 메시지에 여러 상품이 있어도 상품마다 개별 주문으로 생성한다. 여러 상품을 하나의 주문으로 묶는 주문은 링크주문에서만 가능하다 |
| R-ORD-004 | 현장결제의 결제상태 | 현장결제는 주문경로와 관계없이 결제대기로 생성한다. 생성 시점에 결제완료인 결제수단은 카드결제뿐이다 |

### 나. 결제상태·결제완료 일시

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-ORD-005 | 결제상태와 처리상태의 독립 | 결제상태(결제대기 / 결제완료 / 결제취소)와 처리상태는 서로 독립으로 관리한다 |
| R-ORD-006 | 결제취소 전환 시점 | 결제취소는 취소승인·반품승인이 확정되는 시점(구매자 즉시취소 포함)에 전환하는 종결 상태이며 결제확인 등 다른 조작으로 되돌릴 수 없다. 결제대기 상태에서 취소·반품승인된 건도 결제취소로 전환한다. 별도의 [결제취소] 버튼은 없으며 진입점은 [취소처리]·[반품처리]·조정 모드 승인뿐이다 |
| R-ORD-007 | 카드결제 건의 결제취소 처리 | 카드결제 건은 [승인] 시 시스템이 PayApp에 결제취소를 요청하고 성공 응답을 확인한 뒤에만 취소·반품승인을 확정한다. 결제상태 결제취소, 재고 반영, 알림 발송도 이 시점에 한다. 결제취소가 실패하면 승인을 확정하지 않고 요청 상태를 유지하며 실패 안내 후 재시도한다 (→ OI-R-03) |
| R-ORD-008 | 계좌이체·현장결제 건의 결제취소 처리 | 계좌이체·현장결제 건은 승인 즉시 결제취소로 전환한다. 환불 이행은 판매자가 직접 처리하며 결제취소는 취소 처리 확정을 뜻하고 환불 이행 완료를 뜻하지 않는다 |
| R-ORD-009 | 결제확인 | [결제확인]은 결제상태가 결제대기인 주문에만 노출하며 누르면 결제상태만 결제완료로 전환한다. 처리상태에는 영향을 주지 않는다. 취소·반품 요청·승인 상태인 주문에는 노출하지 않는다 |
| R-ORD-010 | 완료 처리 시 결제상태 자동 전환 | 픽업완료·배달완료 확인 팝업에서 처리 시점에 결제상태가 결제대기이면 시스템은 완료 처리와 동시에 결제상태를 결제완료로 전환한다. 따라서 완료 이후에는 결제대기 건이 없다 |
| R-ORD-011 | 결제완료 일시의 기록 시점 | 카드결제는 주문 생성 시점에 결제완료 일시를 기록한다. 계좌이체·현장결제는 [결제확인] 처리 시점, 또는 결제확인 없이 픽업완료·배달완료되어 결제완료로 전환된 시점에 기록한다 |
| R-ORD-012 | 결제완료 일시의 보존 | 결제취소로 전환되어도 결제완료 일시는 삭제하지 않고 보존한다. 결제총액은 결제상태가 아니라 결제완료 일시가 기간 내인지로 집계하며 취소·환불액을 별도로 차감한다 |
| R-ORD-013 | 취소·반품 승인 일시의 기준 | 취소·반품 승인 일시는 카드결제는 PayApp 결제취소 성공 응답을 확인한 일시, 계좌이체·현장결제는 취소·반품을 승인한 일시다. 결제취소가 아닌 건에는 표기하지 않는다 |
| R-ORD-014 | 결제대기 취소 건의 매출 제외 | 결제대기 상태로 취소된 주문은 결제완료 일시가 없으므로 매출조회에 집계하지 않는다. 환불이 없으므로 환불구분도 표시하지 않는다 |
| R-ORD-015 | 결제취소 건의 환불구분 표시 | 환불이 있는 결제취소 건은 환불구분(전체환불 / 부분환불)을 목록·주문상세 결제정보에 함께 표시한다 |

> **경고** 카드결제 건의 승인은 PayApp 결제취소 성공 응답을 확인한 뒤에만 확정한다. 응답이 지연되거나 수신되지 않을 때의 처리는 확정되지 않았다 (→ OI-R-03).

### 다. 처리상태 전이

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-ORD-016 | 처리상태의 순차 진행 | 처리상태는 다음단계 버튼으로 한 단계씩만 진행한다. 주문접수에서 곧바로 완료 단계로 진입하거나 단계를 건너뛸 수 없다 |
| R-ORD-017 | 완료 처리의 확인 | 픽업완료·배달완료는 직전 단계(픽업대기, 배달중)일 때만 노출되는 다음단계 버튼과 확인 팝업("주문번호 OOO 건을 [단계] 처리하시겠습니까?")을 거쳐야 진입한다 |
| R-ORD-018 | 취소·반품 중 처리상태 비움 | 취소·반품이 진행 중이거나 종결(취소·반품요청, 취소·반품승인)된 주문은 처리상태 값을 비우고(표시 "-") 다음단계·되돌리기 버튼을 모두 없앤 뒤 취소·반품 전용 처리 영역으로 대체한다 |
| R-ORD-019 | 반려 시 처리상태 복귀 | 취소·반품이 반려되어 종결된 주문은 처리상태가 요청 이전 상태로 복귀해 정상 트랙으로 다시 집계한다 |
| R-ORD-020 | 처리시점의 갱신 | 다음단계·일괄변경·되돌리기·반려 복귀로 처리상태가 바뀔 때마다 처리시점을 갱신한다. 주문상세는 `[처리상태] 처리시점` 한 줄로 표기하며 처리상태가 비워진 건에는 표기하지 않는다 |
| R-ORD-021 | 되돌리기 | 되돌리기는 직전 단계로만 복귀하며 누르면 즉시 반영하고 확인 팝업은 없다. 주문접수, 완료(픽업완료·배달완료), 취소·반품요청, 취소·반품승인 상태에서는 제공하지 않는다 |
| R-ORD-022 | 목록 [결제확인]의 노출 조건 | 목록의 [결제확인]은 처리상태가 주문접수인 결제대기 건에만 노출하며 현장결제 건은 목록에 노출하지 않는다. 픽업대기 단계의 결제대기 건은 [결제·픽업완료]로 결제와 완료를 함께 처리하므로 목록에는 노출하지 않고 주문상세에서만 처리한다 |
| R-ORD-023 | [결제·픽업완료] | 픽업대기 단계이면서 결제상태가 결제대기인 픽업 주문의 완료 버튼 명칭은 [결제·픽업완료]다. 확인 팝업에서 완료 처리와 함께 결제상태를 결제완료로 전환한다 |
| R-ORD-024 | 일괄변경의 대상 | 일괄변경은 주문목록에서 현재 페이지에 선택한 건만 대상이다. 옵션은 픽업대기 / 배달대기 / 배달중이다. 완료 처리, 취소·반품처리(노쇼처리 포함), 결제확인은 일괄변경 대상이 아니다 |
| R-ORD-025 | 일괄변경의 반영 조건 | 선택한 주문 중 조건을 만족하는 건만 반영하고 나머지는 변경 없이 제외한다. 처리 완료 후 선택을 해제한다 |

## 3.4 절차·상태 전이

처리상태 전이는 3.3절의 전이표·관리 버튼 표를 따른다.

취소·반품 처리 흐름

| 경로 | 흐름 |
| --- | --- |
| 구매자 즉시취소 | 소매몰 [주문취소] → 확인 팝업 → (카드 결제완료 건은 PayApp 결제취소 성공 확인) → 취소승인 확정, 처리상태 비움, 판매가능수량·보유수량 복원, 알림 발송 |

# 4장. 채팅주문 (R-CHT)

## 4.1 적용 범위

- 대상 화면: 소매관리 > 주문관리 > 채팅주문설정(오픈채팅방 연동, 매칭 실패 건), 소매관리 > 상품관리의 채팅주문 허용 입력 영역, 소매관리 > 회원관리 > 회원정보 상세의 회원주문 코드·채팅주문 닉네임
- 대상 계정: 소매몰을 운영하는 본사·가맹점 계정
- 제외 범위: 주문 생성 후의 결제·처리상태·취소·반품(→ 3장 R-ORD), 알림톡 발송 설정(→ 02 파일 A-NTF), 회원주문 코드·닉네임의 회원 단위 규칙(→ 2장 R-MEM), 판매상태·노출여부 실효값(→ 04 파일 W-PRD)

## 4.2 정의

| 용어 | 정의 |
| --- | --- |
| 채팅주문 | 판매자가 연동한 오픈채팅방에 소비자가 정해진 형식의 메시지를 보내면 시스템이 파싱해 접수하는 주문 채널 |
| 채팅주문상품명 | 채팅 파싱에 쓰도록 상품마다 지정하는 짧은 이름. 몰에 노출되는 정식 상품명과 별개 |
| 회원주문 코드 | 회원을 식별하는 숫자 4자리 값. 메시지 끝에 붙인다 |
| 채팅주문 닉네임 | 회원이 오픈채팅방에서 쓰는 발신 닉네임. 회원정보에 선택 항목으로 등록하며, 등록하지 않은 회원은 채팅주문을 이용할 수 없다 |
| 매칭 실패 건 | 회원 확인에 실패해 자동 접수되지 않고 큐에 대기 중인 메시지 |
| 상품 파싱값 | 원문 메시지에서 추출한 상품명·수량 문자열 |
| 매칭 적용 | 관리자가 매칭 실패 건의 회원을 직접 확인해 주문접수 건을 생성하는 처리 |
| 접수 대상 상품 | 채팅주문을 허용하며 현재 판매 중이고 소매몰에 노출 중인 상품 |

판매상태·노출여부는 저장값이 아닌 실효값으로 판정한다. 실효값 기준은 04 파일 W-PRD를 따른다.

| R-CHT-007 | 채팅주문상품명 중복확인 | 채팅주문상품명은 [중복확인]을 통과해야 저장할 수 있다. 중복확인을 하지 않았거나 확인 후 값을 수정했으면 "채팅주문상품명 중복확인을 먼저 완료해주세요."로 저장을 막는다 |
| R-CHT-008 | 채팅주문상품명 유일성 기준 | 채팅주문상품명은 접수 대상 상품 전체를 기준으로 유일해야 한다. 중복 대상은 같은 판매자 내 판매 중이며 노출 중인 상품이다. 판매를 종료(비노출 전환 또는 품절)한 상품이 쓰던 이름은 다른 상품이 재사용할 수 있다. 중복이면 "이미 등록된 채팅주문상품명입니다."로 막는다 |
| R-CHT-009 | 판매 재개 시 이름 중복 재검사 | 판매를 종료한 상품을 노출 + 판매중으로 되돌리는 저장에서는 저장 시점에 채팅주문상품명 중복을 다시 검사한다. 현재 판매 중이며 노출 중인 다른 상품이 같은 이름을 쓰면 "이미 등록된 채팅주문상품명입니다. 채팅주문상품명을 변경한 뒤 중복확인을 완료해주세요."로 저장을 막는다. 노출 또는 판매가 되지 않는 상태로 저장하면 이 검사를 적용하지 않는다 |

| R-CHT-018 | 형식 미인식 메시지 | 접수 형식이 아니거나 접수 대상 상품과 일치하는 상품명이 없는 메시지는 매칭 실패 큐에 쌓지 않고 기록도 남기지 않는다. 소비자에게 안내하지 않는다 |

| R-CHT-023 | 판매가능수량·보유수량 차감 | 주문접수 건이 생성되는 즉시 매칭된 상품의 판매가능수량과 보유수량에서 주문 수량을 차감한다 (→ R-ORD-052 판매가능수량·보유수량의 접수 시 차감) |
| R-CHT-024 | 픽업가능기간 스냅샷 | 주문마다 해당 상품의 픽업가능기간(시작일~종료일)을 주문에 저장한다. 노쇼후보 판정과 알림톡 픽업기간 변수에 이 값을 쓴다 |
| R-CHT-025 | 주문일시 기록 시점 | 주문일시는 주문접수 건을 생성하는 시각으로 기록한다. 자동 접수는 메시지 수신 시각, 매칭 적용은 매칭 적용 시각이다. 한 메시지에서 생성한 주문은 같은 주문일시를 갖는다 |
| R-CHT-026 | 접수 알림톡 대체 | 채팅주문은 주문접수완료 알림톡을 발송하지 않고 채팅방 접수 안내로 대체한다. 결제확인완료·픽업대기·픽업완료·취소/반품승인 알림톡은 발송한다 (→ A-NTF-033 소매 신규주문접수의 케이스 구분) |

### 사. 매칭 실패 건 관리

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-CHT-030 | 매칭 회원 조회 | 매칭 모달은 입력한 회원주문 코드로 회원을 조회한다. 원래 메시지의 코드를 기본값으로 채우고 조회 가능하면 결과 카드를 미리 표시한다. 코드가 비어 있으면 "회원주문 코드를 입력해주세요.", 4자리가 아니면 "회원주문 코드는 숫자 4자리로 입력해주세요.", 회원이 없으면 "일치하는 회원이 없습니다."를 표시한다 |
| R-CHT-031 | 매칭 시 도용 판단 | 매칭 모달은 조회한 회원의 이름·연락처·등록 닉네임·이용상태를 보여준다. 등록된 닉네임이 없으면 닉네임을 "-"로 표시한다. 관리자가 수신 닉네임과 등록 닉네임을 직접 비교해 도용 여부를 최종 판단한다 |
| R-CHT-032 | 이용제한 회원의 매칭 차단 | 조회한 회원이 이용제한이면 결과 카드에 경고를 표시한다. [매칭 적용]을 눌러도 "이용제한 회원에게는 주문접수를 생성할 수 없습니다."로 막는다 (→ R-MEM-016 이용제한 회원의 채팅주문 매칭) |
| R-CHT-033 | 회원 확인 선행 | 회원을 확인하지 않고 [매칭 적용]을 누르면 "회원주문 코드로 회원을 먼저 확인해주세요."로 막는다 |
| R-CHT-034 | 매칭 적용 시 상품 검증 | 파싱한 상품명이 접수 대상 상품과 하나라도 일치하지 않으면 "채팅주문상품명과 일치하지 않습니다: (상품명)"으로 막는다. 카탈로그가 일치하면 상품별로 판매가능수량("판매가능수량이 부족합니다: (상품명) 현재 N개")과 1회 최대구매수량("1회 최대구매수량을 초과했습니다: (상품명) 최대 N개")을 검증한다. 여러 사유가 겹치면 함께 표시한다 |
| R-CHT-035 | 매칭 적용의 전체 차단 | 매칭 적용에서는 상품 중 하나라도 검증에 걸리면 전체를 차단하며 일부만 접수하지 않는다. 차단한 건은 큐에 남고 소비자에게 시스템 안내를 발송하지 않는다. 관리자가 사유를 확인해 해당 건을 삭제하고 채팅방에서 소비자에게 직접 안내한다 |
| R-CHT-036 | 매칭 적용의 생성 결과 | 검증을 통과하면 상품마다 픽업·현장결제, 결제대기·주문접수의 주문접수 건을 생성하고 판매가능수량과 보유수량을 차감하며 채팅방에 정상 접수 안내를 발송한다. 매칭을 완료한 건은 매칭 실패 목록에서 즉시 삭제한다 |
| R-CHT-037 | 매칭 실패 건 삭제 | 매칭 실패 건은 [삭제]를 확정하면 목록에서 완전히 제거하며 복구할 수 없다. 삭제 시 주문접수 건을 생성하지 않고 별도 이력을 남기지 않는다. 삭제 확인 창에 "삭제한 데이터는 복구할 수 없습니다. 신중하게 삭제해 주세요."를 표시한다 |
| R-CHT-038 | 일괄삭제 범위 | 일괄삭제는 현재 페이지에서 선택한 건만 대상으로 한다. 페이지를 이동하면 선택을 해제한다. 선택한 건이 없으면 "삭제할 매칭 실패 건을 선택해주세요."를 표시한다 |

> **경고** 매칭 실패 건 삭제는 복구할 수 없다. 삭제한 메시지의 원문·상품 파싱값은 다시 확인할 수 없다 (→ R-CHT-037 매칭 실패 건 삭제).

> **주의** 시스템은 소비자 안내 문구를 일곱 가지 상황에만 발송한다. 매칭 실패 큐 대기, 매칭 적용 차단, 형식 미인식은 안내가 없으므로 관리자가 채팅방에서 직접 안내한다 (→ R-CHT-029 소비자 발송 문구).

## 4.4 절차·상태 전이

자동 접수 흐름

| 단계 | 처리 |
| --- | --- |
| 1 | 오픈채팅방에서 메시지를 수신한다. 접수 형식이 아니면 무시한다 (→ R-CHT-018) |
| 2 | 메시지 끝 코드로 회원을 조회하고 닉네임을 대조한다. 실패하면 매칭 실패 큐에 쌓는다 (→ R-CHT-016, R-CHT-017) |
| 3 | 회원이 이용제한이거나 닉네임이 등록되지 않았으면 주문을 생성하지 않고 소비자에게 안내한다. 둘 다 해당하면 이용제한 안내를 우선한다 (→ R-CHT-016, R-CHT-027) |
| 4 | 상품별로 재고·1회 최대구매수량을 판정한다. 통과한 상품만 개별 주문으로 생성하고 소비자에게 안내한다 (→ R-CHT-020, R-CHT-021) |

수동 매칭 흐름

| 단계 | 처리 |
| --- | --- |
| 1 | 관리자가 매칭 실패 건의 [매칭]을 눌러 모달을 연다 |
| 2 | 회원주문 코드로 회원을 확인하고 닉네임을 비교한다 (→ R-CHT-030, R-CHT-031) |
| 3 | [매칭 적용]에서 이용제한·상품·재고·최대구매수량을 검증한다. 하나라도 걸리면 전체를 차단한다 (→ R-CHT-032, R-CHT-034, R-CHT-035) |
| 4 | 통과하면 주문접수 건을 생성하고 목록에서 삭제한다 (→ R-CHT-036) |

## 4.5 예외·실패

| 상황 | 처리 |
| --- | --- |
| 파싱한 상품 전체가 접수 가능 | 상품마다 주문접수 건을 생성하고 소비자에게 안내한다 |
| 일부 상품만 접수 가능(자동 접수) | 접수 가능한 상품만 생성한다. 접수분과 미접수분의 사유를 함께 안내한다 (→ R-CHT-021) |
| 재고부족·판매가능수량 초과 | 해당 상품 주문을 생성하지 않고 소비자에게 안내한다 (→ R-CHT-027) |
| 1회 최대구매수량 초과 | 해당 상품 주문을 생성하지 않고 소비자에게 안내한다 (→ R-CHT-027) |
| 이용제한 회원의 주문 시도 | 주문을 생성하지 않고 소비자에게 안내한다 (→ R-CHT-027) |
| 닉네임 미등록 회원의 주문 시도 | 주문을 생성하지 않고 소비자에게 안내한다. 매칭 실패 큐에는 쌓지 않는다 (→ R-CHT-027) |
| 코드 불일치 또는 닉네임 불일치 | 매칭 실패 큐에 쌓고 소비자에게 안내하지 않는다 (→ R-CHT-028) |
| 매칭 적용 시점에 카탈로그 불일치·재고부족·최대구매수량 초과 | 매칭 적용을 차단하고 건은 큐에 남긴다. 시스템 안내는 없다 (→ R-CHT-035) |
| 형식 미인식 메시지 | 큐 적재, 기록, 안내 모두 하지 않는다 (→ R-CHT-018) |
| 매칭 모달에서 이용제한 회원 매칭 적용 | 제출 시점에 차단한다 (→ R-CHT-032) |
| 채팅주문상품명 미입력·중복확인 미완료 상태에서 상품 저장 | 저장을 막는다 (→ R-CHT-006, R-CHT-007) |

## 4.6 연계

| 대상 | 연계 내용 |
| --- | --- |
| 2장 R-MEM | 회원주문 코드·닉네임 등록, 이용제한 회원의 주문 차단 |
| 3장 R-ORD | 생성한 주문의 결제·처리상태 전이, 취소·반품, 판매가능수량·보유수량 차감 |
| 5장 R-CST | 채팅주문 취소·반품요청은 소매몰 주문내역에서만 한다 |
| 02 파일 A-NTF | 채팅주문 알림톡 발송 기준 |
| 04 파일 W-PRD | 채팅주문 허용 상품의 판매상태·노출여부 실효값 |

# 5장. 소매몰 주문내역·취소·반품 (R-CST)

## 5.1 적용 범위

- 대상 화면: 09SCM 소매몰(소비자 화면) 마이페이지 > 주문내역, 취소요청·반품요청, 취소요청 상세·반품요청 상세
- 대상 사용자: 소매몰에 로그인한 회원 본인
- 제외 범위: 관리자의 취소·반품 처리(승인·반려·직권 처리, 환불 입력, 재고 반영)(→ 3장 R-ORD), 채팅주문 접수(→ 4장 R-CHT), 관리자·소비자 알림 발송 기준(→ 02 파일 A-NTF)

## 5.2 정의

| 용어 | 정의 |
| --- | --- |
| 주문내역 | 로그인한 회원 본인의 소매 주문 목록. 링크주문과 채팅주문을 구분하지 않고 함께 표시한다 |
| 즉시취소 | 소비자가 [주문취소]로 판매자 승인 없이 취소승인으로 확정하는 처리 |
| 취소요청 | 소비자가 [취소요청]으로 접수하며 판매자 승인·반려로 확정하는 처리 |
| 반품요청 | 소비자가 완료 주문에 접수하며 판매자 승인·반려로 확정하는 처리 |
| 완료일시 | 픽업완료 또는 배달완료로 전환된 일시 |
| 처리 주체 | 취소·반품을 처리한 주체. 즉시취소는 "구매자 즉시취소"로 표시한다 |

처리상태, 결제상태, 취소·반품 상태, 환불구분은 00 공통 3-3~3-5를 따른다.

## 5.3 요건

### 가. 주문내역 조회

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-CST-001 | 주문내역의 조회 대상 | 주문내역은 로그인한 회원 본인의 모든 소매 주문을 표시한다. 링크주문과 채팅주문을 구분하지 않는다 |
| R-CST-002 | 채팅주문의 상품별 표시 | 채팅주문은 상품마다 개별 주문이므로 주문내역에도 상품별 개별 주문으로 표시하며 상품별로 취소요청·반품요청을 할 수 있다 (→ R-CHT-020 상품별 개별 주문) |
| R-CST-003 | 소비자 화면의 결제상태 값 | 결제상태는 결제대기·결제완료·결제취소 세 값만 표시한다. 환불완료 값은 쓰지 않는다. 취소·반품승인이 확정되면 결제취소로 표시하고 상태 아래에 전체환불 또는 부분환불을 보조 텍스트로 표시한다. 결제대기 상태에서 취소된 건에는 보조 텍스트를 표시하지 않는다 |

### 나. 버튼 노출 조건

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-CST-004 | 주문취소 버튼 노출 조건 | [주문취소]는 처리상태가 주문접수이고 취소·반품 이력이 없으며, 결제수단이 카드결제이거나 결제상태가 결제대기일 때 노출한다 (→ R-ORD-038 구매자 즉시취소의 대상·결과) |
| R-CST-005 | 취소요청 버튼 노출 조건 | [취소요청]은 처리상태가 주문접수이고 취소·반품 이력이 없으며, 결제수단이 계좌이체 또는 현장결제이면서 결제상태가 결제완료일 때 노출한다 |
| R-CST-006 | 반품요청 버튼 노출 조건 | [반품요청]은 처리상태가 픽업완료 또는 배달완료이고, 완료일시로부터 7일 이내이며, 취소·반품 이력이 없을 때 노출한다. 7일이 지난 완료 주문에는 노출하지 않는다 (→ R-ORD-034 소비자 반품요청 기한) |
| R-CST-007 | 요청 상세 버튼 노출 조건 | [취소·반품 상세]는 취소·반품 이력이 있으면 요청·승인·반려 상태와 관계없이 노출한다. 즉시취소 건은 취소승인 상태로 표시하고 처리 주체를 "구매자 즉시취소"로 표시한다 |
| R-CST-008 | 소비자 취소 불가 단계 | 픽업대기·배달대기·배달중 단계는 상품 준비가 시작된 상태이므로 소비자는 취소할 수 없다. 이 단계의 취소는 공급자 직권 취소만 가능하다 (→ R-ORD-033 소비자 취소 가능 시점) |

### 다. 즉시취소

| ID | 요건명 | 요건 |
| --- | --- | --- |
| R-CST-009 | 즉시취소 입력·확인 | 즉시취소는 사유를 입력받지 않고 확인 팝업만 거친다. 확인하면 즉시 처리한다. 카드결제 건의 팝업 문구는 "주문과 카드결제가 즉시 취소됩니다.", 결제대기 건은 "결제대기 주문이므로 주문이 즉시 취소됩니다."이다 |
| R-CST-010 | 즉시취소의 확정 결과 | 즉시취소는 판매자 승인 없이 취소승인으로 확정한다. 처리상태는 비우고, 카드결제 건은 결제를 전액 취소해 결제취소로 전환하며, 결제대기 건은 환불 없이 결제취소로 전환한다 (→ R-ORD-039 즉시취소의 재고·결제 처리) |
| R-CST-011 | 즉시취소 실패 시 소비자 동작 | 카드 결제취소(PayApp)가 실패하면 취소를 처리하지 않고 주문은 기존 상태를 유지한다. 소비자가 다시 취소를 시도한다. 결제취소 성공 응답을 확인한 뒤에만 취소승인을 확정한다 (→ R-ORD-040 즉시취소의 카드 결제취소 실패) |
